# Drawing Composition

[◀ Prev: Fill Defects](2.1-fill-defects.md) · [Contents](README.md) · [Next: Icon Formats ▶](3.0-icon-formats.md)

This page states the RIPscrip 2.x drawing contract inherited by 3.0. It separates geometry, source-color selection and the operation on the destination. The [3.0 drawing delta](../../3.0/techspecs/2.3-drawing-composition.md) applies these rules to POINT and reconstructed skewed contours. RIPscrip 1.54 has a narrower command/mode matrix and is unchanged.

**Sources:** ALPHA 4 §3.4.1.57 WRITE_MODE, §3.4.1.47 SET_BORDER, §3.4.1.29 LINE_STYLE, PIXEL's Write Mode attribute, and the fill-style definitions. The specific border exception controls over WRITE_MODE's general scope. [Derivation and source boundaries](../../3.0/research/issues-74-76-drawing-contract.md).

## Operations and operands

Let S be the source color, D the destination immediately before this contribution, and M the all-ones mask for the active color value. Clip geometry first; an uncovered pixel receives no contribution.

| W mode | Operation | Result    |
| ------ | --------- | --------- |
| 00     | COPY      | `S`       |
| 01     | XOR       | `S XOR D` |
| 02     | OR        | `S OR D`  |
| 03     | AND       | `S AND D` |
| 04     | NOT       | `D XOR M` |

NOT ignores S. In an indexed 16-color example M=0x0F; in a 256-color example M=0xFF. Palette lookup follows the logical indexed-color operation; do not substitute an operation on unrelated host RGBA bytes. RGB drawing applies the same Boolean operations to the resolved color bits; this contract specifies no alpha blending.

`RIP_WRITE_MODE` governs PIXEL, standalone line/curve/polygon outlines, region fills and graphics text where their attributes say Write Mode. It is an output rule, independent of the backend API. A color-replacement-only pixel/rectangle/glyph call cannot implement XOR, OR, AND or NOT without additional composition.

**Different NOT operation:** bitmap PUT/LOAD commands have their own mode field. Their mode 04 complements the **source image** (`S XOR M`); drawing W04 complements the **destination** (`D XOR M`). For S=0x3C and D=0xA5 with M=0xFF, those are 0xC3 and 0x5A respectively. Global W is not an extra operation to apply after a command's explicit bitmap mode.

The 3.0 profile specifies mixed indexed/RGB operands and destination selection on a shared terminal and graphics canvas. [3.0 drawing color operands](../../3.0/techspecs/2.3-drawing-composition.md#drawing-color-operands-on-mixed-surfaces).

## Source selection and gaps

A standalone stroke uses Draw Color on its line-pattern on bits. A transparent line gap contributes nothing; an opaque line gap uses Back Color as S. These gap policies are the documented LINE_STYLE off_draw values 0 and 1. Internal client state bits are not additional protocol parameters. A primitive explicitly limited to solid outlines uses Draw Color throughout its stroke, so the line-gap policy has no effect there.

Region filling uses Fill Color on one bits of the fill pattern and Back Color on zero bits. A zero fill-pattern bit is a background-colored contribution, **not** a transparent line gap. Fill pattern 00 therefore fills with Back Color. Polygon holes, determined by the fill rule, are genuinely outside the fill region and receive no fill contribution.

## Filled objects and border order

The protocol defines two **logical** phases: fill the region using current W; then, if N enables the border, stroke the outline using **COPY**. The border uses Draw Color and current line thickness. Polygon-related borders also use the current line pattern; the documented circle/ellipse/pie/rectangle/rounded-rectangle borders are solid. The backend may combine calls only when its result is equivalent to these phases.

A border contribution copies its selected Draw/Back Color over the already-filled destination. It does not apply W again to that pixel. N does not alter the stored W or line/fill style. N0 suppresses the outline, including closing edges and any radial contour segments; it does not change the fill rule or fill operands. BAR is explicitly borderless and is unaffected by N.

Let O mean the requested opaque line-gap policy. This table applies to a nonempty filled region:

| Border state | Gap policy O | Logical phases | Border-gap result |
| --- | --- | --- | --- |
| N0 | Transparent | Fill using W | No border contribution |
| N0 | Opaque | Fill using W | No border contribution |
| N1 | Transparent | Fill using W, then COPY outline | Pattern gaps retain the fill/destination underneath |
| N1 | Opaque | Fill using W, then COPY outline | Pattern gaps COPY Back Color |

For solid-only borders, the last column is inapplicable: there are no line-pattern gaps. A region with no area has no fill phase. If its preserved contour includes a nonzero outline segment, N1 draws that segment with the border rule and N0 draws nothing. This covers a radial fallback without creating an exception to N.

## Repeated visits and polygon fill

Separate drawing contributions operate sequentially on the latest destination. Two genuine visits by the same standalone XOR stroke restore D; two NOT visits restore D; OR and AND are idempotent for a repeated identical S. Replacing all visits by a single coverage union changes XOR/NOT and is incorrect. Shared endpoints/joins are not automatically two visits merely because two adjacent segment records mention the same vertex; exact join/edge pixel coverage is outside this abstract contract.

A polygon's repeated traversal instead participates in its specified fill rule. For even-odd filling, two complete coverings produce a hole, three produce an interior. Evaluate that region first and apply its fill operation once; do not emit one fill operation per winding. Its optional border is still COPY, so repeated identical border visits are idempotent. Distinct fill commands, unlike windings within one polygon, are separate sequential operations.

## Independent pixel vectors

All values below are hexadecimal logical 8-bit colors. D=0xA5, Draw Color=0x3C, Fill Color=0x3C, border Draw Color=0x0F and Back Color=0x66. Geometry membership is given; these are not assertions about exact edge rasterization. The [machine-readable vectors](data/drawing-operations.json) and `run/check-drawing-contract` verify the arithmetic and the published rows.

| Contribution                     | COPY | XOR  | OR   | AND  | NOT  |
| -------------------------------- | ---- | ---- | ---- | ---- | ---- |
| Point or fill foreground         | 0x3C | 0x99 | 0xBD | 0x24 | 0x5A |
| Fill-pattern zero bit            | 0x66 | 0xC3 | 0xE7 | 0x24 | 0x5A |
| Standalone stroke on bit         | 0x0F | 0xAA | 0xAF | 0x05 | 0x5A |
| Transparent standalone gap       | 0xA5 | 0xA5 | 0xA5 | 0xA5 | 0xA5 |
| Fill then solid border           | 0x0F | 0x0F | 0x0F | 0x0F | 0x0F |
| Fill then transparent border gap | 0x3C | 0x99 | 0xBD | 0x24 | 0x5A |
| Fill then opaque border gap      | 0x66 | 0x66 | 0x66 | 0x66 | 0x66 |
| Two standalone stroke visits     | 0x0F | 0xA5 | 0xAF | 0x05 | 0xA5 |
| Two separate foreground fills    | 0x3C | 0xA5 | 0xBD | 0x24 | 0xA5 |
| Hole or disabled radial outline  | 0xA5 | 0xA5 | 0xA5 | 0xA5 | 0xA5 |

The POINT thick-square case applies the first row once to each covered pixel, not once per unit of thickness. The same matrix applies to screen and offscreen destinations. A known filled full-pie radial stroke uses the border row when enabled; disabling N removes that contribution. These distinctions preserve contour topology while separating it from the drawing operation.
