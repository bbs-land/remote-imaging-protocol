# 3.1 Column Text System

[◀ Prev: 3.0 Text Output & Fonts](3.0-text-output-and-fonts.md) · [Contents](README.md) · [Next: 4.0 Icons & Bitmaps ▶](4.0-icons-and-bitmaps.md)

_Reconstructed edition - every claim carries an evidence tag; see [Contents](README.md) for the legend._

A **flowed-text column system**: rectangular column regions, chained so prose pours from one into the next, paginated into overflow buffers and paged through with buttons.

Nothing in the published 1.54 or 2.00 Alpha 4 specifications resembles it, and there is no v1.54 or v2.0 counterpart to this page - the entire mechanism is reconstructed here from the RIPtel demo corpus, in which TeleGrafix left a field-map comment that decodes the core command. The [White Paper](../text/RIPScrip-3.x-technical-whitepaper.txt) points at it - to display "high-quality documents like those you would normally find in magazines or newspapers … you'd need to familiarize yourself with the multi-column system for extensive layout control" - RIPtel's help lists "multiple-column text displays ('news articles')" among RIPscrip 3.x's features, and the demo's own FONTSTOR.TXT advertises that "a powerful column system is" provided.

_Evidence: WP; HLP; corpus (FONTSTOR.TXT)._

## Defining a Column Region - `1e`

_Evidence: DLL (RIPtel 3.1’s RIPscrip 3.0.7 driver); corpus (FONTS.RIP crib, NEWSPAPR.RIP and other scenes). The [derivation and reproduction note](../research/issue-4-column-overflow.md) identifies the exact artifact, instruction ranges and original-routine probes. These findings replace the earlier corpus-only hypotheses._

### RIP_EXTENDED_BEGIN_TEXT

_Define a column and select its article_

The driver calls this operation `RIP_BeginExtendedText()`; `RIP_EXTENDED_BEGIN_TEXT` is this reference’s existing editorial name.

|  |  |
| --- | --- |
| **Level** | 1 |
| **Command** | `e` |
| **Arguments** | `x0:XY y0:XY x1:XY y1:XY column:1 article:1 flags:4 highlight:2 reserved:8` followed by an optional search-word string |

**Format:** `!|1e <x0> <y0> <x1> <y1> <column> <article> <flags> <highlight> <reserved> <search-words>` **Example:** `!|1e4L3D919K0100010000000000`

All numeric fields use the current base math; each `XY` uses the current coordinate width. With two-character coordinates the fixed block is 24 characters. The driver normalizes each pair of corner coordinates into ascending order, records inclusive widths (`x1-x0+1`), and converts the rectangle from world to device coordinates when it is defined. Text uses the current font and drawing attributes when flowed; a definition does not capture a private font or copy of the article’s prose.

FONTS.RIP’s crib is `xxyyxxyycaffffccrrrrrrrr`. Its previously unknown `cc` field is the highlight palette index:

| Field | Meaning and validation |
| --- | --- |
| Four `xx`/`yy` coordinates | Opposite rectangle corners in world coordinates |
| `c` | Global column slot, 0..35 |
| `a` | Article, 1..35; defining a region also selects it |
| `ffff` | Only 0..3 accepted; bit 0 enables this article’s overflow retention; bit 1 enables search-word highlighting in this column |
| `cc` | Highlight color index, 0..255 when bit 1 is set; ignored otherwise |
| `rrrrrrrr` | Consumed but ignored |
| String tail | Search words when bit 1 is set; otherwise ignored |

Search words are expanded as text variables, trimmed, split on whitespace, and compared case-insensitively against complete text tokens. Matching changes the drawing color to `cc`; it does not paint a highlight rectangle. Up to eight words of at most sixteen bytes each are stored. An empty/whitespace-only list, an overlong word, or an out-of-range highlight index rejects the definition. A ninth word reports “Too many search words (8 max)” but installs the first eight. Unknown flag bits reject the command. Numeric identifier/flag errors are checked before modifying the definition. A protected drawing port suppresses the operation.

Bit 0 belongs to the **article**, while bit 1, color and search list belong to the **column**. Every successful `1e` definition overwrites its article’s overflow-enable setting: the last column definition for that article wins. Use consistent bit 0 settings across a chain.

The example decodes in base 36 to rectangle (165,121)-(325,344), global column 0, article 1, overflow enabled, highlighting disabled, ignored color 0 and reserved zero. It does not append or render text by itself.

## Column Content - Raw Text Lines and `1E`

_Evidence: DLL; corpus (NEWSPAPR.RIP, N2_HORO.RIP, NEWS.RIP)._

After defining/selecting a nonzero article, raw text flows into its columns. Lines without a RIP command introducer are prose; RIP commands can still set attributes, add regions or read a file. Ordinary line endings are reflowed; blank lines separate paragraphs. An example inline block is:

```text
!|1e0F3M434G0100000000000000
Southern California was pounded
with nearly two weeks of rain.
Hundreds left homeless as a result.
!|1E
```

[`1E`](3.0-text-output-and-fonts.md#rip_end_text) flushes the pending line, closes that article’s overflow output streams and deactivates text flow. It retains the selected article, column definitions, page counters and saved files. The scene-end `#` also reaches this end operation. Neither operation is an overflow reset.

## Chained Columns and Streams

_Evidence: DLL; corpus (DEMO-01.COL, N2_HORO.RIP, NEWSPAPR.RIP)._

There are **36 global column slots**, each assigned to one article, and 35 nonzero articles for raw text flow. Flow visits defined slots in increasing numeric order, skipping holes and columns assigned to other articles. Neither definition order nor rectangle position sorts the chain. A chain may begin at any slot and need not be contiguous.

The horoscope page uses slots 0,1,2 of article 1:

```text
!|1e083G5K9S0100000000000000
!|1e6120BP9S1100000000000000
!|1eC420HK9S2100000000000000
```

The newspaper’s secondary story uses global slot 3, article 2 (`1eA17FH48Y3200010000000000`). Defining slot 0 for article 2 would replace slot 0’s previous assignment to article 1; it would not create a second article-local slot 0.

### Redefinition and selection

A definition replaces the chosen slot, reassigns its owner, closes the target article’s overflow output handles, and resets its current column to “before the first column.” Its next prose starts at the lowest matching slot. Existing drawn pixels are not a retained text model and are not reflowed automatically.

The article’s current page, known forward-page limit and “complete source already captured” flag survive redefinition. Thus a continuation template can redefine its rectangles and re-read the current saved page without returning to page zero. Reassignment affects the new owner’s state; it does not reset the previous owner’s page counters.

Selecting a different article first flushes the old article’s pending line. Selecting the same article clears the pending word/line buffers without flushing them; a same-article redefinition can therefore discard unfinished prose. Define the complete chain before feeding its text, as the demos do. Selection alone does not rewind an already established article cursor; a definition is what resets it to the first column. The selector operation observed in NEWS.RIP is `1A`; its separate wire-layout reconciliation remains in [issue #2](https://github.com/bbs-land/remote-imaging-protocol/issues/2).

### The Legacy Form - `1T` With Column/Stream Digits

_Evidence: DLL; corpus (NEWS.RIP, N2_TITLE.RIP)._

The inherited [`1T`](3.0-text-output-and-fonts.md#rip_begin_text) uses the same rectangle/column helper. Its trailing two digits are separate one-digit column and article numbers, not one reserved two-digit number. Both accept 0..35; article zero is accepted for this compatibility form, but the raw-byte article feeder requires a selected article greater than zero, and the end-text helper returns immediately for article zero. Use articles 1..35 for the raw-flow and pagination contract. `1T` does not set the article’s overflow-enable flag or install/reset extended search settings; it retains those settings. On fresh state, overflow is disabled.

NEWS.RIP builds four columns of article 1:

```text
!|1T285CHC7001
!|1T0U71HCOW11
!|1TN45CYO9N21
!|1TI89OYNOW31
```

N2_TITLE.RIP supplies prewrapped lines using [`1t`](3.0-text-output-and-fonts.md#rip_region_text): `1t1` fully justifies a line, while `1t0` leaves it left aligned. This is separate from feeding a raw prose stream and letting the engine wrap it.

## Flowing Whole Files - `1R` on Plain Text

_Evidence: DLL; corpus (NEWSPAPR.RIP, DRAGON.RIP, FONTS.RIP)._

An open article can receive prose from [`1R`](5.5-file-transfer-and-queries.md#rip_read_scene):

```text
!|1e4L3D919K0100010000000000
!|1e9L4SDF681100010000000000
!|1eDP4SHI5V2100010000000000
!|1R00000000$&MAIN_STORY$
!|1E
```

The demos’ `.TXT` targets are ordinary prose with no RIP introducers. Their text is wrapped into the selected article’s columns. A variable such as `$&MAIN_STORY$` supplies the filename; `$OVERFLOW(1,CUR)$` supplies a saved-page filename. These expressions return filenames, not the text content itself. Keep layout definitions and story text separate to reuse a template with different copy.

## Pagination - `$OVERFLOW$` and `$RESET(OVERFLOW)$`

_Evidence: DLL; corpus (DEMO-01.COL, DEMO-02.COL, NEWSPAPR.RIP)._

Overflow is **lazy file-backed retention**, not an eagerly computed page list. When enabled, the first source feed at page 0 saves the complete incoming source as page 0. Text beyond the last column is saved as the remainder for page 1. Rendering page 1 can create page 2, and so on. With overflow disabled, prose beyond the last column is discarded.

For each article let `P` be the zero-based current saved-page index and `H` the known forward limit. Both start at 0. Creating a remainder while rendering P sets H to P+1; reaching the end of the source without creating a remainder leaves H unchanged. Re-rendering an earlier page may reduce H by replacing it with that earlier page’s newly generated remainder index. H is not an eagerly measured total or a permanent maximum of all files ever created. Displayed page numbers are P+1.

Saved-page names use `%03hu%c%04ld.OVR`: an instance identifier, a one-character article number (`1`..`9`,`A`..`Z`), and the zero-based page number with at least four decimal digits. For instance identifier 7, article 1, page 0 is `00710000.OVR`. Treat the returned name as an opaque local read-scene target; formatting a name does not establish that its file exists.

The macro accepts zero to three parameters. No parameters means current filename of the selected article; one means current filename of that article. An explicit article is decimal 1..35, or `CUR` for the selected article. Names are case-insensitive. `CUR` can resolve to article zero after a reset, in which case a filename query returns `<NONE>`.

| Form | Result and side effect |
| --- | --- |
| `$OVERFLOW(n,CUR)$` | Current filename if overflow enabled, otherwise literal `<NONE>`; no movement or existence check |
| `$OVERFLOW(n,PAGE)$` | Decimal P+1, even when overflow disabled |
| `$OVERFLOW(n,NEXT)$` or `…,NEXT,SET` | If enabled and P<H, close output handles, increment P and return an empty string |
| `$OVERFLOW(n,PREV)$` or `…,PREV,SET` | If enabled and P>0, close output handles, decrement P and return an empty string |
| `…,NEXT,SETVERBOSE` / `…,PREV,SETVERBOSE` | Same movement; at a boundary show the notification described below |
| `…,NEXT,QUERY` | Filename for P+1 if enabled and P<H, else `<NONE>`; no movement |
| `…,PREV,QUERY` | **Shipped defect:** filename for P+1 whenever enabled, else `<NONE>`; neither a P>0 test nor a decrement |
| `…,CUR,QUERY` / `…,PAGE,QUERY` | Same as CUR/PAGE without the third parameter |
| `$OVERFLOW(n,k)$`, decimal k | If enabled and k≤H, close output handles, set P to k and return an empty string; k is zero-based |
| `$OVERFLOW(n,RESET)$` | Close handles; disable overflow; clear P, H and source-capture flags; retain column definitions, selection and column cursor; empty-string result |

The numeric page assignment has a shipped signed-16-bit truncation: accepted values 32768..65535 become negative, and 65536 becomes 0. Use 0..32767 for a valid nonnegative page index. This truncation follows the k≤H test. Numeric parameters must consist of decimal digits; negative spellings reject.

For NEXT/PREV, an absent or empty third parameter acts as SET. Other third parameters reject; CUR/PAGE allow only QUERY when a third parameter is present, and numeric selection/RESET require exactly two parameters. Too many parameters, invalid article/operation/mode, disabled overflow for a modifying operation, or a numeric page beyond H report an error. No navigation occurs on these errors.

A NEXT at P=H or PREV at P=0 **aborts the surrounding macro evaluation**, retaining the current page and skipping the rest of that response, including a following `$>template$`. SETVERBOSE additionally displays a `Cannot Continue` notification with `End of document.` or `Beginning of document.`. The boundary path returns no string; it is not the same as a successful empty-string expansion. This abort is local to the evaluation: the next evaluation clears it.

`$RESET(OVERFLOW)$` is a **global layout and overflow-state reset**: close all article output handles, remove all column definitions, deactivate flow, select article 0, clear pending text and all page/source-capture state. It does not call file deletion: old physical files may remain, but are no longer represented by live paging state. Redefine the columns to start another article. The drawing reset `*` also removes columns and disables overflow, but retains page counters/source-capture flags; do not substitute it for `$RESET(OVERFLOW)$` when starting new copy.

## The `.COL` Page Template - Worked Example

_Evidence: DLL; corpus (NEWS.RIP, NEWSPAPR.RIP, DEMO-01.COL)._

A successful pager button first changes P, then replays the continuation template. The template redefines the columns and reads the current filename; it does not itself advance P:

```text
!|1M00VWG0WUH01000000ID=6:$overflow(1,prev,setverbose)$$>demo-01.col$
!|1M00WUG0XUH01000000ID=7:$overflow(1,next,setverbose)$$>demo-01.col$
!|y0000000C000000001a1a000000dixon
!|1e4L3D919K0100010000000000
!|1e9L4SDF681100010000000000
!|1eDP4SHI5V2100010000000000
!|1R00000000$overflow(1,cur)$
!|1E
```

The following states are protocol oracles independent of pixel metrics. Whether a particular source produces a remainder depends on the font and device geometry; neither script fixes one universal total page count.

| Example / event | Expected article state |
| --- | --- |
| NEWS.RIP from fresh state | `1A` selects article 1; `1T` defines global slots 0..3, all owned by article 1; overflow remains off; P=H=0; displayed PAGE=1 |
| NEWS.RIP exceeds its four columns | Excess prose discarded; NEXT/PREV modifying forms report “Overflow not active”; no saved remainder is implied by the mere existence of columns |
| NEWSPAPR.RIP after `$RESET(OVERFLOW)$` | No columns, selected article 0, all P=H=0 and retention off |
| NEWSPAPR.RIP after main story and secondary story | Article 1 owns slots 0..2, article 2 owns slot 3; both retention flags on; each P=0; each H=1 iff its initial story produced a remainder, otherwise 0; each `1E` deactivates flow and closes outputs |
| NEXT for article 1 when H=1 | P becomes 1; displayed PAGE becomes 2; template redefinition retains P; reading page 1 leaves H=1 if it fits, or sets H=2 if another remainder is produced; article 2’s page state is unchanged |
| PREV from P=1 | P becomes 0; displayed PAGE becomes 1; the template reads the complete saved source; reflow can regenerate page 1 and set H=1 |
| NEXT on final rendered page P=H | P and H unchanged; verbose end notification; macro evaluation stops before replaying the template |
| PREV on P=0 | P and H unchanged; verbose beginning notification; no template replay |
| End of article (`1E` or `#`) | Flow inactive, handles closed; page counters, selection and columns retained |
| Per-article RESET | That article’s retention off, P=H=0 and source-capture flags clear; its definitions/cursor and other articles retained |
| Global `$RESET(OVERFLOW)$` | All article/layout state reset as above; no automatic redraw or replay |

A deterministic original-routine oracle in `run/riptel-column-probe` uses a ten-unit column, ten-unit line advance, unit character widths and a sixteen-word source. It observes eight pages, complete source retention at index 0, one new remainder per replay, all sixteen words in order, boundary abort, and a forward limit reduced from 7 to 1 when page 0 is rendered again. This checks state semantics with controlled metrics; it does not claim to reproduce the newspaper’s pixels.

## Drop Caps

_Evidence: corpus (NEWS.RIP)._

NEWS.RIP demonstrates a typographic flourish the column system does not do natively - the author fakes it, instructively. A single oversized character is drawn at the first column's corner with plain `@` ([RIP_TEXT_XY](3.0-text-output-and-fonts.md#rip_text_xy)) in a large Marin face, and the flowed article text simply **starts mid-word**:

```text
!|y00003W0e040000001k1a000000Marin      Large display face
!|@A91Gª                                One extended-ASCII character (byte 0xAA) at the corner
!|y0000300U000000001k1a000000Marin      Back to the body size
wo years ago, TeleGrafix Communications stunned the computer industry with
```

The article reads "**T**wo years ago…" - the capital lives outside the flow, the byte `0xAA` presumably selecting an ornamental capital _T_ in the Marin outline font's extended range _(hypothesis)_. The flowed text wraps around nothing; the first column's region is simply drawn to start below/right of the cap.

## The Newspaper Demo - Showcase

_Evidence: corpus (NEWSPAPR.RIP, N2_TITLE.RIP, N2_HORO.RIP, N2_BUSI.RIP, N2_PHOTO.RIP, TWEATHER.RIP, DEMO-01.COL, DEMO-02.COL, STORY01.TXT, STORY02.TXT)._

The system's full showcase is an **electronic newspaper**, and TeleGrafix built it as a customizable product, not a canned screen. NEWSPAPR.RIP opens with a configuration block under the comment _"Change these to the values you want for your content"_:

```text
!|1^[0000$-=MAIN_STORY=story01.txt$|!     Filename containing main story
!|1^[0000$-=MAIN_AUTHOR=Jeff Reeder$|!    Author of main story
!|1^[0000$-=MAIN_TITLE=Rapid RIPscrip-3 Rocks The Net$
!|1^[0000$-=SUB_STORY=story02.txt$|!      Filename containing secondary story
```

The front page then draws a masthead in outline fonts, an "INSIDE" sidebar of four inline teaser columns (each an independent `1e` … `1E` block), the main headline as `@4L2L$&MAIN_TITLE$`, bylines as `By $&MAIN_AUTHOR$`, three chained columns flowing `$&MAIN_STORY$`, a boxed secondary story on stream 2 flowing `$&SUB_STORY$`, three captioned JPEG photographs (`1i`/`1p` - see [4.1 JPEG Images](4.1-jpeg-images.md)), and a navigation strip of mouse fields into the section pages - weather map, horoscopes (chained inline columns), business, and a JPEG photo gallery. Overflow from both stories pages into DEMO-01.COL and DEMO-02.COL. Swap two `.TXT` files and two title variables and it is _your_ newspaper - layout, pagination and navigation come free. Nothing else in the RIPscrip corpus, of any era, demonstrates this much of the 3.x design working together.

## Related research

The selector used by NEWS.RIP is `RIP_SelectArticle` (`1A`), established by the shipped handler and article-state consumer. Its full wire-layout reconciliation remains tracked in [issue #2](https://github.com/bbs-land/remote-imaging-protocol/issues/2).
