# 9.3 Host Command & Control Character Reference

[◀ Prev: 9.2 Version Identification Reference](9.2-versions.md) · [Contents](README.md)

_Reconstructed edition - every claim carries its evidence; see the [Contents](README.md) evidence legend._

Everything the terminal sends back to the host in the 3.x generation - control-character notation, host-bound response sequences, and keyboard emulation - plus the ANSI sequences a host sends to control RIPscrip processing.

## Control-character notation in host commands

The second ordinary host-response pass processes caret and backquote notation. For example, `^M` emits one CR byte (`0d`) and `^@` emits two literal bytes (`5e 40`). [Control-byte rules and key sequences](5.0-host-commands.md#control-characters) · [Original scanner and captures](../research/issue-53-host-control-brackets.md).

## Host-bound responses

| Trigger or response expression | Response or effect | Reference |
| --- | --- | --- |
| `ESC[!` or `ESC[0!` auto-sense query | `RIPSCRIP030001` (14 ASCII bytes), no NUL/CR/LF; disabled queries do not reply; see generic profile | [9.2](9.2-versions.md), [1.1](1.1-protocol-and-command-hierarchy.md#ansi-sequences-auto-sensing) |
| `ESC[3!` auto-sense query | `RIPSCRIP030001` plus one engine CR when enabled; client output translation may add LF | [9.2](9.2-versions.md#engine-replies-and-terminators) |
| `$RIPVER$` text variable | The same 14-byte identification phrase, no ending | [5.1](5.1-text-variables.md#ripver) |
| Mouse field click | The field's `<text>` host command (with `ID=n:` identity prefix support and inline conditionals), control characters and text variables expanded | [4.2](4.2-mouse-fields-and-pointer.md#rip_mouse), [5.0](5.0-host-commands.md#mouse-field-identities---idn) |
| Button click / hotkey | The button's host-command block, after template/macro processing (incl. `<<NAME>>` macros and `<<IF>>` conditionals) | [4.3](4.3-buttons.md#rip_button), [5.2](5.2-templates-and-conditionals.md) |
| RIP_QUERY mode 0 | Executes immediately and sends the resulting nonempty host response | [Immediate query](5.5-file-transfer-and-queries.md#rip_query) |
| RIP_QUERY modes 1–4 | Store or clear expressions. The definition sends no query response. RIPtel 3.1 has no click trigger for these modes. | [Stored click modes](5.5-file-transfer-and-queries.md#stored-click-modes-and-historical-intent) |
| RIP_QUERY modes 5/6 | Store or clear handlers without a reply. Eligible mouse-field entry (5) or exit (6) can later send the expanded response. | [Hover definitions](5.5-file-transfer-and-queries.md#resident-hover-definitions) |
| `$TERMINFO()$` | Terminal product name | [TERMINFO](5.1-text-variables.md#terminfo) |
| `$TERMINFO(LIST)$` | Comma-delimited information keywords, for example `LIST,NAME,VENDOR,VERSION` | [TERMINFO](5.1-text-variables.md#terminfo) |
| `$IFS(JPEG)$` | ASCII `1` when JPEG is supported, `0` otherwise | [IFS](5.1-text-variables.md#ifs) |
| `$IFS(LIST,_AUDIO)$` | Comma-delimited feature keywords in the audio category | [IFS](5.1-text-variables.md#ifs) |
| `$IFS()$` | Argument error | [IFS](5.1-text-variables.md#ifs) |
| RIP_FILE_QUERY modes 00-04 | Exact engine table: mode 00 `1`/`0` without ending; 01..03 use CR; 04 uses `1.N:S.date.time` or full `0.N:0.00/00/00.00:00:00`, plus CR. Open failure is silent; metadata failure keeps `1` with zeros. Client output may add LF | [5.5](5.5-file-transfer-and-queries.md#rip_file_query) |
| RIP_ENTER_BLOCK_MODE upload refused by user | Alpha 4 specifies ten CAN bytes at 100 ms intervals. RIPtel 3.1’s timed refusal reply is unestablished. | [5.5](5.5-file-transfer-and-queries.md#rip_enter_block_mode) |

Within authored HCL host-command text, mouse-coordinate and state variables substitute into the response - see [9.1 Text Variable Reference](9.1-text-variable-reference.md). Protocol replies such as FILE_QUERY are sent as already formatted bytes and are not reparsed as HCL. Variables may also be set (`$-=NAME=value$`) and dereferenced (`$&NAME$`) inside host commands before transmission ([5.0](5.0-host-commands.md#setting--reading-user-variables-from-host-commands)).

## Keyboard emulation

RIPtel's terminal-emulation keystrokes (ANSI vs VT-102) are per-Setup/Bookmark client configuration, outside the RIPscrip language - see the [baseline terminal reference](../../baseline/techspecs/ansi-vt-support.md). _Evidence: HLP (Terminal Emulation topics)._

## Host-to-terminal ANSI control

| Sequence | Effect |
| --- | --- |
| `ESC[!` | Query RIPscrip version (terminal answers, above) |
| `ESC[0!` | Same as `ESC[!` |
| `ESC[1!` | Disable RIP framing while retaining normal ANSI enable handling; no reply |
| `ESC[2!` | Enable RIP framing without resetting parser state; no reply |
| `ESC[3!` | Query version with final CR; no response while RIP is disabled |

_Evidence: DLL; [original buffer/ANSI/control and exact reply probes](../research/issue-7-framing-identification.md). The [generic reply profile](9.2-versions.md#generic-implementation-profile) and [ESC priority rules](1.1-protocol-and-command-hierarchy.md#esc-priority-and-resumption) distinguish identity policy from parser behavior._
