## Identification phrase

The inherited format is **`RIPSCRIPxxyyvs`**, totaling 14 ASCII bytes: `xx` is the two-digit language major version, `yy` the two-digit minor version, `v` a vendor code and `s` that vendor’s subversion digit. Vendor 0 is generic/unspecified, 1 RIPterm/TeleGrafix, 2 Qmodem Pro. These last two digits are not a two-digit language revision. [1.54 identity history](../../1.54/ripscrip/9.2-versions.md) and the [2.0 record](../../2.0/ripscrip/9.2-versions.md) preserve the earlier evidence.

## Known 3.0 identification strings

| String | Reading / standing | Provenance |
| --- | --- | --- |
| `RIPSCRIP030001` | Language 03.00, generic vendor 0, subversion 1; complete 14-byte phrase | Original RIPtel 3.1 DLL literal RVA `0x803b0`; autosense callback `0x355d9`, RIPVER callback `0x4b6c1`; original-routine native checks (DLL) |
| `RIPSCRIP030001` | Same bytes; SyncTERM’s separately configured RIP 3 reply | SyncTERM `ripver[]`, `ripper.c:7619`, sent with length 14 at `18447` (ST) |
| `RIPSCRIP03000` | Incomplete 13-character printed quote; not the full executable response | RIPTEL.HLP FAQ’s login-timeout example (HLP) |

The earlier claim that RIPtel’s reply could not be recovered from its binaries is superseded by the literal and its actual consumers in the unchanged original DLL. RIPtel’s product version **3.1**, driver build **3.0.7**, supported language **3.0**, and the phrase’s vendor/subversion fields identify different things.

## Engine replies and terminators

The following table assumes the [normal ANSI text path](1.1-protocol-and-command-hierarchy.md#esc-priority-and-resumption). ESC is byte 0x1b. The returned value is the exact engine-produced string, before any client-configured output translation.

| Request | RIP enabled | RIP disabled |
| --- | --- | --- |
| `ESC[!` / `ESC[0!` | `RIPSCRIP030001`, no ending | No response |
| `ESC[1!` | Disable; no response | Remain disabled; no response |
| `ESC[2!` | Remain enabled; no response | Enable; no response |
| `ESC[3!` | `RIPSCRIP030001` then CR (0x0d) | No response |
| `$RIPVER$` or `$RIPVER()$` in an allowed macro context | Return the phrase `RIPSCRIP030001`, no ending | Not an autosense request; expansion depends on the caller context |

Default/0 phrase bytes are **`52 49 50 53 43 52 49 50 30 33 30 30 30 31`**. Selector 3 appends **`0d`**. No NUL is sent: the C-string storage terminator is not a wire byte. RIPVER accepts no arguments and adds no CR/LF; a surrounding host command can supply its own control characters. The original client may translate a supplied CR to CRLF according to its output setting, as recorded in the [reply-path trace](../research/issue-5-scene-headers.md#entry-point-effect-probes-and-client-reply-trace); default/0 have no CR to translate.

The autosense callback uses the first ANSI parameter only, ignores later parameters and sends no reply for other selector values; private-prefix `?0!` is a different ANSI dispatch. The ordinary ANSI decimal accumulator wraps to 16 bits. Enable/disable changes the emulation flag without resetting buffered parser state; [checked stream examples](1.1-protocol-and-command-hierarchy.md#esc-priority-and-resumption) distinguish this from a scene reset.

## Generic Implementation Profile

**Allowed by this reconstructed specification:** an independent implementation supporting the 3.0 contract may identify itself as **`RIPSCRIP030000`**: language 03.00, generic vendor 0, vendor subversion 0. It need not claim TeleGrafix vendor code 1 or copy a product name. This is an explicit interoperability policy using the inherited generic-vendor allocation, not a newly discovered historical response or a distinct RIPscrip language version.

| Context | Exact generic-profile bytes |
| --- | --- |
| Enabled `ESC[!` or `ESC[0!` | `RIPSCRIP030000` (14 bytes), no NUL/CR/LF |
| Enabled `ESC[3!` | `RIPSCRIP030000` plus one CR (15 bytes total) |
| `$RIPVER$` | Value `RIPSCRIP030000`, no ending; surrounding host text controls subsequent bytes |
| Disabled query 0/3 | No reply; retain ANSI enable handling |

Generic phrase hex: **`52 49 50 53 43 52 49 50 30 33 30 30 30 30`**. A complete default reply is those 14 bytes and nothing else. Hosts may recognize the `RIPSCRIP03` prefix for a RIP 3 family while accounting for the complete phrase and the requested terminator policy.

## `$RIPVER$` documentation oddity

RIPTEL.HLP’s example `RIPSCRIP015300` is stale 1.53-era documentation, also carried in the 1.54 specification. It is not the value returned by this original 3.0 driver, and the shortened FAQ quote is not a separate autosense value. See the [1.54 example note](../../1.54/ripscrip/9.2-versions.md).
