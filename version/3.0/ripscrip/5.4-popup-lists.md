# 5.4 Pop-Up Lists

[Derivation and source limits](../research/issue-159-pick-list-contract.md). Earlier-version [2.0](../../2.0/ripscrip/5.4-popup-lists.md) and [1.54](../../1.54/ripscrip/5.4-popup-lists.md) records remain separate._

Pop-up pick lists offer choices while building an eligible [HCL response](5.0-host-commands.md). Selecting an entry splices its **original response bytes** into the working response; canceling an optional list inserts empty. A list is recognized only when that consumer enables pick lists. Permission to use ordinary text variables in another filename/label/metric consumer does not independently enable modal lists there. Pixel-exact dialog styling, font rasterization and OS widgets are outside this profile.

## Syntax and Source Spans

```text
((*x,y:Question::response@Description,response@Description,...))
```

The required marker, position, question and descriptions are optional. The simplest list is `((A,B))`.

| Element | Meaning |
| --- | --- |
| `((` … `))` | First opener recognized by the scanner and first following **unescaped** close; no parenthesis nesting counter |
| Immediate `*` after `((` | Require a selection; it is consumed before position/question parsing |
| `x,y:` / `x,:` / `,y:` / `,:` | Optional decimal position prefix; omitted axes center. See the [portable placement contract](#position-prefix-and-placement) |
| `Question::` | First unescaped `::` before the close separates an explicit prompt from choices; no whitespace trimming |
| `response` | Original source span returned on selection; display cleanup never rewrites it |
| `@Description` | First unescaped @ separates response from display label; without it, the response also supplies the label |
| Comma | Unescaped choice separator |
| Backslash plus next byte | Quoting pair skipped by close/separator scans; retained in the original response span |
| `_h_` / `~h~` | Display hotkey markup; first marked character is the hotkey. It does not modify the returned response |

All scanners work on bytes. Backslash quotes the next byte for delimiter recognition; double/single quotes have no delimiter-protection role. Thus `A\,B` is one response, `A\@B` contains a literal response @, and `A\)\)` does not terminate the list. Escape at least one colon to keep `::` inside data instead of making it the prompt separator. These list-level quoting pairs are distinct from [wire framing](1.1-protocol-and-command-hierarchy.md) and the later HCL backslash pass; each layer receives the bytes left by its caller.

No unescaped nested list is parsed as a balanced child. An unescaped `((` inside a response is ordinary list data to this close finder; the first eligible `))` still closes the outer list. Do not add nesting depth 64 or a fresh recursive interpreter call from the legacy SyncTERM implementation.

### Prompt, Entries and Display

The original stock prompt for **absent** `Question::` is **`Please enter requested value`**. An explicitly blank prompt, `((::A,B))`, is **empty**, not the default. This corrects the inherited `Choose one of the following:` wording for this identified client. For an explicit prompt, retain its first **60 raw bytes**, then remove backslash quoting pairs; do not evaluate dollar/template/control codes in display text.

Entries retain their order. A leading comma or consecutive commas creates an empty entry with an empty response/label. A trailing comma creates **no additional final empty entry**. An empty response with a description, as in `@Nothing`, is selectable and returns empty. Spaces are data. A second unescaped @ in a description makes the closed list malformed; quote a description @ when it is literal.

Display text is separate from response text: normalize `_` to `~`, remove backslash quoting pairs, and interpret the first marked character as a hotkey. Remaining markers affect highlighting only; an unmatched marker highlights the remainder under the inherited markup rule. These operations execute no HCL providers. Markers are not escapable as literal hotkey punctuation merely by preceding them with a backslash: display normalization still gives them markup meaning. Put markup in a description when it must not be transmitted. For `Sysop@_S_ysop`, selecting returns `Sysop`; without @, selecting `_S_ysop` returns those original underscore bytes.

**Explicit safe display bound:** use at most the first **60 raw bytes of each chosen display-label source** before normalization/dequoting. The original allocator caps its allocation calculation at 60 while its subsequent copy is not a bounded long-label contract. This profile truncates safely without executing or requiring that path. The full original response span remains independently available for selection; a long response without @ can have a short displayed label and a longer returned value. A dangling backslash left at a display truncation boundary contributes no quoted next byte and is omitted from display; do not read beyond the retained span.

`*` is special **only immediately after the opener**, before position/question parsing. It prevents optional cancel/ESC; it does not select an entry automatically. In `((Q::*A,B))`, the first response is literally `*A`: choosing B still returns B, choosing the first returns `*A`, and a dialog is required. To express a first response beginning with `*` without accidentally requiring selection, use an explicit prompt separator or quote that response byte. Whitespace before `*` makes it data, not the required marker.

## Ordinary Passes and Transmission

_Evidence: original response executor 0x4acd9, scanner 0x4b0e4, list branch 0x4b305 and splice path 0x4b25b; [pass derivation](../research/issue-159-pick-list-contract.md#static-parsing-and-pass-ledger)._

The ordinary HCL response runs **two ordinary passes**, after its existing angle preprocessing/block preparation. The first pass's `0xff5f` mask defers controls and backslash decoding but **retains pick-list bit 0x10**. Lists are eligible in both passes when enabled by the consumer. A chosen/canceled result replaces the whole original list, and the scan continues **after the inserted bytes in the current pass**. Selection does not call the top-level interpreter, restart preprocessing, resegment inserted text into new HCL commands or add an extra pass.

| Where list/selection becomes available | Required processing |
| --- | --- |
| List present when pass one reaches its opener | Show/resolve it in pass one. Its inserted response is skipped for the rest of that pass; pass two can process eligible directives in those bytes |
| List inserted by an earlier dollar/template result in pass one | That insertion is skipped in pass one; the list becomes eligible in pass two |
| List selected in pass two | Insert its raw selected response and skip it. No third ordinary pass, so dollar/control/playback/list syntax newly inserted there remains raw |
| A pass-one selected response contains a dollar variable | Pass two can evaluate it. A further directive in the variable's returned value is inserted/skipped and receives no third pass |
| A pass-one selected response contains `^m` or a playback token | Pass two can decode/execute it under the existing [control/playback rules](5.3-local-playback.md). A pass-two selection containing the same bytes leaves them raw |
| Escaped list-looking bytes become literal parentheses through pass-two backslash decoding | The decoder skips each quoted next byte; it does not rescan newly unquoted openers. With no later pass they remain literal list-looking text |

Complete the two passes before the response executor sends/echoes its final bytes. **No prefix of this response is transmitted before selection.** For `order ((apples,oranges))`, while the modal list awaits input the host has received neither `order ` nor an answer from this response; choosing apples yields one final response `order apples`. Canceling the optional list instead yields `order `. The 3.x white paper's prefix-before-dialog narrative and SyncTERM recursion/auto-answer paragraph do not describe this shipped path.

Earlier providers/local playback or already completed **separate** HCL blocks retain their ordinary effects; withholding a response prefix is not global transaction rollback. Canceling a list is not a hard expansion abort. Further lists/providers in the remaining source proceed normally. A required list cannot be canceled to manufacture an empty result, although a legitimate chosen empty response is allowed.

## Limits, Empty Lists and Malformed Source

| Boundary | Rule |
| --- | --- |
| Available choices | First **64** parsed entries; additional entries are not offered or validated as choices. The full close-delimited expression is still consumed |
| Selected response | First **1023 raw source bytes**, in the original caller's 1024-byte buffer including terminating NUL. Truncate before insertion/later-pass decoding; NUL is storage, never transmitted |
| Explicit question | First 60 raw bytes, then dequote |
| Display label | Explicit safe completion: first 60 raw bytes, then normalize/dequote |
| Whole list / working response | No separate shipped total-list 1024-byte check in this path. Apply the existing [4096-byte working-prefix rule](5.2-templates-and-conditionals.md#response-and-embedding-byte-limit) before/during expansion. A list over 1024 can be valid within that retained prefix |
| Empty entire choice set, including `((::))` / `((*::))` | **Portable completion:** consume the closed expression and insert empty without showing an unselectable modal list. A required marker does not create an entry or an endless dialog |
| Found close but malformed entry structure | Consume the complete expression through that first close and insert nothing; continue the ordinary scan/next HCL command. No prefix is sent early and no dialog must be shown |
| No eligible closing `))` in this pass | No list consumption and no modal list. Continue normal byte scanning at the opener, so later dollar/control syntax still has its usual effects. A later pass may recognize a list formed by earlier expansion; otherwise the unclosed text remains ordinary response bytes |

A list closed within the retained working prefix can use all of that source; selected-response/display bounds remain separate. If the 4096-byte cap removes its close, do not retrieve discarded bytes, repair its delimiter or show a list from the discarded suffix. A bounded malformed/empty result is not a whole-program syntax abort. Normal allocation/provider failures retain their existing consumer error semantics; this profile adds no native failure-recovery or storage-overrun requirement.

## Position Prefix and Placement

The immediate prefix after optional `*` is recognized only as ASCII decimal digit runs and punctuation: **`digits,digits:`**, **`digits,:`**, **`,digits:`** or **`,:`**. Leading zeros are decimal. There is no Base Math/UltraNum decoding, sign, whitespace, fraction or exponent form. If no complete recognized prefix exists, leave those bytes in the question/choices and center both axes; a stray numeric-looking prefix is not silently discarded. Parse the question separator after any accepted position prefix.

**Explicit bounded portable placement:** accept each supplied decimal value in **0..65535** using checked/wide arithmetic. An out-of-range digit run makes the whole position prefix unrecognized; do not wrap, consume a prefix of the number or partially apply one axis. For each present axis use its corresponding active WORLD and physical DEVICE extent, truncating the nonnegative ratio `value * DEVICE_extent / WORLD_extent` toward zero. An omitted axis, or one with zero WORLD extent, centers independently. Do not add the current PORT/viewport/TW origin or clip the modal list to its viewport.

Place the modal rectangle on the available client surface: a supplied axis is an offset from that surface's origin, an omitted axis centers the measured dialog on it. Clamp/fix the final rectangle to that surface after measurement; for surface extent C and dialog extent D, fit an offset into `[0,max(C-D,0)]`. Centering uses `max(floor((C-D)/2),0)`. Oversized dialogs pin at the origin and must keep choices accessible by scrolling or an equivalent mechanism. Exact chrome, size measurements, hotkey glyphs and OS/window-manager screen positioning remain implementation-defined.

The original numeric helpers narrow to signed words (and a signed byte in the Y-only path), use the X-conversion argument for both supplied axes and include host-specific far-edge adjustments. Those static facts and their exact limits are [recorded separately](../research/issue-159-pick-list-contract.md#static-parsing-and-pass-ledger). The canonical rule above is the explicit consistent world-position intent; it does not require those asymmetric narrowing/scaling paths or claim native pixel equality.

## Independent Parsing and Pass Vectors

Each example is the ordinary HCL source **after wire framing**. Backslashes below are actual bytes at that stage. Selection is supplied by a user; these vectors execute no original dialog. Variable A is a permitted existing value, and no optional provider failure occurs.

| Source / chosen action | Expected result |
| --- | --- |
| `pre((A,B))post`, choose B in pass one | Default prompt `Please enter requested value`, two labels A/B; final response `preBpost`. No prefix sent before choice |
| Same source, cancel | Final response `prepost`; continue later HCL commands |
| `((::A,B))`, choose A | Explicit blank prompt, final A |
| `((Q::*A,B))`, choose first / B | Prompt Q, first response `*A`; final `*A` / B respectively. No auto-answer |
| `((10,:Q::A))` | Accepted X=decimal 10, centered Y, prompt Q, one response A |
| `((,100:Q::A))` | Centered X, accepted Y=decimal 100, prompt Q, one response A |
| `((,A,,B,))` | Four choices: empty, A, empty, B; no fifth trailing entry |
| `((A\,B@One\@Label,C))`, choose first in pass one | One displayed label `One@Label`; response span is raw `A\,B`, becoming final `A,B` through pass-two quoting |
| `((A\)\),B))`, choose first in pass one | The escaped closes do not end the list; final response `A))` |
| `((Q::A@D@E,B))TAIL` | Closed malformed description: consume list, no modal selection, final TAIL; next HCL command proceeds |
| `pre((A`, with no other special bytes | No close/list/dialog/consumption in either pass; final literal `pre((A`; next HCL command proceeds |
| `((::))` / `((*::))` | Zero choices: explicit portable no-dialog empty result |

Use A=`$SHIFT$` with a controlled normal SHIFT result 1. A source list `((Q::$A$))` selected in pass one inserts `$A$` without evaluating it there; pass two evaluates A and inserts/skips `$SHIFT$`, so the final response is literal **`$SHIFT$`**, not 1. A direct pass-one selection of `$SHIFT$` instead yields 1 in pass two. For A=`((Q::$SHIFT$))` and source `$A$`, pass one inserts/skips the list; selecting it in pass two leaves literal `$SHIFT$` with no third evaluation.

A direct pass-one selection of `^m` yields CR in pass two. If A=`((Q::^m))`, source `$A$` first makes that list available in pass two, whose selection leaves literal `^m`. Playback tokens follow the same pass boundary: only a token already present when a permitted ordinary pass reaches it can run; pass-two selection does not immediately execute its inserted playback token.

For escaped nested-looking bytes, use source `((\(\(A\,B\)\)))` and select its sole response in pass one. Pass two unquotes/skips each parenthesis/comma, producing literal **`((A,B))`**, with no second dialog or third pass. If those raw escaped bytes are instead selected in pass two, the backslashes also remain raw. An unescaped inner close would have ended the original outer expression earlier; this vector does not establish balanced nesting.

For limits, a 1024-byte raw selected response returns its first 1023 bytes regardless of a short description. A 61-byte raw label displays only its first 60 under the safe rule while its response remains separately capped at 1023. A 61-byte explicit question similarly uses its first 60 before dequoting. A list with 65 short choices offers only the first 64 and removes all 65 source entries on selection. A total list longer than 1024 but fully within the 4096-byte working prefix remains usable; cutting its close out of that prefix follows the missing-close rule.

For placement on a 640×480 surface with WORLD 1280×960 and a measured 200×100 dialog, the X-only 10 example requests X=5 and centered Y=190; the Y-only 100 example requests Y=50 and centered X=220. A request X=1280 converts to 640 and fits back to 440. `65536,:Q::A` is outside the explicit numeric bound and remains prompt text `65536,:Q` with both axes centered; `-1,100:Q::A` likewise has no numeric-position prefix. These are abstract placement/extent vectors, not Windows modal screenshots.
