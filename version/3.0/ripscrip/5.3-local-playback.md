# 5.3 Local File Playback

[◀ Prev: 5.2 Templates & Conditionals](5.2-templates-and-conditionals.md) · [Contents](README.md) · [Next: 5.4 Pop-Up Lists ▶](5.4-popup-lists.md)

_Reconstructed edition - every claim carries an evidence tag; see [Contents](README.md) for the legend._

Local playback directives instruct the terminal to process a file _already on the user's disk_ instead of pulling content over the modem - the client/server heart of the [Host Command Language](5.0-host-commands.md), which the White Paper singles out as the way "to simulate menus on an online service locally, thus making it so that you don't have to transmit hardly anything over the modem." They are prefix [text variables](5.1-text-variables.md), usable from within any host command or query.

_Evidence: WP; 2.00a4; HLP._

All four playback forms share one shape: `$`, a one-character prefix, the filename, `$`. RIPtel searches for the named file in the current host's [connection directory](../../glossary.md) first, then in `ICONS\`, then along the user-configured Search Path (which allowed CD-ROM-resident resources for games) - the [file override](../../glossary.md) lookup order detailed in [6.2 Asset Delivery & Storage](6.2-asset-delivery-and-storage.md#lookup-order-file-override). _Evidence: HLP._

| Directive     | Media                             | Example           |
| ------------- | --------------------------------- | ----------------- |
| `$>FILE.RIP$` | RIPscrip scene (or any text file) | `$>NEWSPAPR.RIP$` |
| `$)FILE.WAV$` | Digitized audio                   | `$)TRAIN.WAV$`    |
| `$<FILE.BMP$` | Bitmap image                      | `$<BRICK.BMP$`    |
| `$(FILE.JPG$` | JPEG photograph                   | `$(ASTRO.JPG$`    |

The bracket mnemonic is deliberate, and inherited from 2.0: angle brackets (`>`, `<`) mark the _low-level_ playback primitives (raw RIPscrip, raw bitmap), while the parentheses (`)`, `(`) mark the _higher-level_ media objects (audio, compressed photos). _Evidence: 2.00a4._

_The 2.0 record this carries forward is [5.3 of the v2.0 reference](../../2.0/ripscrip/5.3-local-playback.md); 1.54 had only `$>file$`, in the [v1.54 page](../../1.54/ripscrip/5.3-local-playback.md)._

## Shared Filename Contract

_Evidence: all four original callbacks call the same name helper after dollar parsing and before media dispatch. [Derivation and source/portable limits](../research/issue-161-playback-filenames.md). This is separate from angle preprocessing, ordinary passes and the adopted JPEG presentation/lifetime contract._

For each reached enabled playback token: parse its filename, uppercase ASCII a..z, copy into owned working storage, substitute the state characters below, then apply media extension/lookup rules. This adds no nested dollar/template/pick-list evaluation. An angle macro can form the reference before parsing; an ordinary insertion follows the existing same-pass skipping rule.

### State Substitutions

| Byte | Replacement and source |
| --- | --- |
| `*` | Current synchronous field callback's numeric **identity**, as unsigned 16-bit decimal, not its table slot. ID 7 gives `7`, ID 0 gives `0`; an unidentified active field's signed FIELDID -1 gives **65535** here |
| `*` outside a field callback | **Empty**. Remove each star; no last-click/hover ID, default zero or prompt |
| `?` | ASCII **1** while the interpreter’s tracked left-held/captured-press bit (MSTAT bit 0) is set, otherwise **0**. This is not field selection, pointer-inside state, an independent physical-button poll or a wildcard |
| `[` | ASCII **1** while Shift is down, otherwise **0** |
| `]` | ASCII **1** while Control is down, otherwise **0** |

Replace every occurrence, mixed or repeated, in every prefix. No preceding-backslash test suppresses these substitutions; they are not glob syntax or HCL template brackets. Other bytes remain unchanged by this helper.

Use the adopted [captured FIELDID scope](5.0-host-commands.md#identity-grammar-and-fieldid-lifetime) across synchronous nested playback/callbacks and deletion/reset. Hover handlers and keyboard actions can supply their own ID; merely hovering between callbacks cannot. The tracked left-held bit is set for an accepted field press and cleared before release-action dispatch; a physical press outside every field does not acquire a RIP capture or set this bit. It remains independent of the current callback ID and can stay set while the captured pointer is dragged outside. Star's unsigned spelling and absent-context empty result are distinct from signed `$FIELDID$` and its unavailable-variable error.

**Explicit coherent-state completion:** capture handler identity and tracked mouse/Shift/Control state once when each filename operation is reached; repeated placeholders use that snapshot. Separate later tokens may observe later state. Do not latch modifiers into stored templates or reread a deleted/replacement field. Transform only the owned name, retaining source definitions, user values, field identity/selection and input flags. Media execution has its own existing effects.

### Dollar Quoting, Bound and Recovery

A filename terminator is a dollar **not immediately preceded by backslash**. At a dollar, a preceding stored backslash is overwritten by that dollar and parsing continues: `\$` contributes **one literal dollar**. This is an immediate-previous-byte rule, not odd/even slash-pair quoting. Two backslashes before a dollar leave one backslash plus the quoted dollar. Other non-NUL filename bytes, including commas, parentheses, quotes and control notation, are copied as name data rather than recursively parsed as HCL arguments/lists/controls. Other backslashes remain literal; there is no general filename quote decoder. Wire framing and outer HCL quoting remain separate stages.

The limit is **20 decoded working-name bytes before state substitution/default extension**, excluding prefix, delimiters and NUL. Twenty are accepted; a 21st ordinary byte rejects the reference without truncated playback. A quoted dollar can finish byte 20 despite occupying two source bytes. Twenty stars can expand to **100 decimal bytes**, then 104 with a default extension; the 20-byte check is not reapplied. Use safe owned storage, without requiring the native buffer layout.

Successful parsing uppercases ASCII a..z in the working name, leaving stored source and reply case unchanged. Retain normal case-insensitive resource lookup; arbitrary locale folding of high bytes is not required.

| Outcome | Token, media and following text |
| --- | --- |
| Valid token, playback enabled (original evaluator bit 0x40) | Transform/attempt once, remove token with **empty replacement text**, continue suffix. A missing/unsupported media resource does not insert a Boolean/name or make the token literal |
| Valid recognized token, playback disabled by consumer | Keep literal, no media or same-name user fallback, under the [existing disabled-feature rule](5.2-templates-and-conditionals.md#eligible-providers-and-rejected-codes) |
| Overlong/malformed filename with an eligible close | No substitution/media call. Keep complete original reference literal and advance past it for this pass; following source/commands proceed. No partial uppercasing/playback |
| No eligible close | No playback; advance from the opener and continue ordinary scanning. Later dollars/controls retain normal roles; do not quarantine the remaining program |
| Valid token becomes empty after substitutions | **Explicit completion:** consume with no lookup/media action, rather than manufacturing a bare default-extension resource |

The 4096-byte working-prefix rule still limits surviving source; discarded terminators cannot be recovered. A token inserted/skipped in pass one can execute in pass two; pass-two insertion receives no third pass. Earlier completed effects are not rolled back.

### Extensions, Lookup and WAV Stop

After substitution, normal bare resource names use:

| Prefix | Extension handling |
| --- | --- |
| `$>` scene | Append **.RIP** when no dot exists; keep explicit extensions such as .FN/.COL/.TXT |
| `$)` waveform | Supply **.wav** when no extension exists; keep an explicit extension. Format validation remains separate |
| `$<` bitmap | Supply **.BMP** without a dot; retain adopted aliases **.ICN→.BMP**, **.HIC→.BMH**, **.MSK→.BMM**, with other extensions following existing media rules |
| `$(` JPEG | Supply **.JPG** without an extension; keep an explicit extension under the existing JPEG consumer |

Lookup remains **configured host connection directory → shared ICONS → user search-path entries** (start at ICONS without a host directory). These local callbacks do not request a missing file from the remote host. Existing media/capability/current-port/style eligibility remains; no new display, transfer, palette or file-deletion guarantee is introduced.

The exact quoted WAV spelling at this parser stage is `$)\$OFF\$$`. It produces filename `$OFF$` and performs ordinary waveform lookup with default **.wav**; it **does not recognize a stop sentinel**. A real local `$OFF$.wav` is an ordinary file, and a missing one is a no-op. Wire `1w` has its separately documented `$OFF$` stop action. Use **`$RESET(SOUND)$`** to stop from HCL. The embedded filename dollar bytes are not evaluated again as a variable.

Native component preparation and extension split/make helpers also handle platform paths. DOS drives/separators, invalid-tail recovery and private buffers do not define another HCL escape grammar or portable permission to address arbitrary host paths. Interoperable source uses bare resource names and the published lookup rules; implementations may document platform path support separately.

### Independent Filename Vectors

These are HCL bytes **after wire framing**, with eligible/present resources unless stated. Expected requests are abstract, with no original file/audio/UI execution. A committed callback has **ID 7**, tracked left-held bit clear, Shift down, Control up.

| Source | Request / reply |
| --- | --- |
| `$>F*?[]$OK` | One scene request **F7010.RIP**; reply **OK** |
| `$)F*?[]$OK` | One waveform request **F7010.wav**; reply OK |
| `$<F*?[]$OK` | One bitmap request **F7010.BMP**; reply OK |
| `$(F*?[]$OK` | One JPEG request **F7010.JPG**; reply OK |
| `$>**??[[]]$OK` | **77001100.RIP**, same snapshot; reply OK |
| `$>F*?[]$OK` outside activation, same input | **F010.RIP**; star empty, other state digits retained |
| Same token in an unidentified active field | **F65535010.RIP**; unsigned identity, not slot/-1 |
| Same token, ID 12/left held/Shift up/Control down | **F12101.RIP** |
| `$>a\$b.fn$OK` | **A$B.FN**, no nested variable; reply OK |
| `$)\$OFF\$$OK` | Attempt **$OFF$.wav**, no stop-sentinel action; reply OK |
| `$>$OK` or `$>*$OK` outside activation | Empty-name no-action completion; reply OK |

Let N20 be twenty ASCII A bytes, N21 twenty-one. For each prefix, a name N20 is accepted and gets its default extension; N21 invokes no media and the reply retains the complete original overlong reference plus OK. Nineteen A bytes plus a quoted dollar has decoded length 20 and is accepted although the source name occupies 21 bytes. Twenty stars with active unidentified identity produce `65535` repeated twenty times before extension, without changing the stored source.

An unclosed `$>ABC` with no other special bytes stays literal and performs no playback; the next separate command proceeds. Unclosed `$>ABC\$` has no eligible terminator: pass two can unquote its trailing dollar during ordinary scanning, yielding literal `$>ABC$`, with no third execution. A valid missing-file `$>MISSING$OK` still replies OK after a local lookup no-op. In a graphical consumer where playback is disabled, a valid token stays literal with no user-variable prompt. A preceding backslash never makes star/question/brackets literal wildcard characters in this filename helper.

## Local Scene Playback - `$>FILE.RIP$`

_Evidence: 2.00a4; HLP; SyncTERM (ripper.c:7967-7970); corpus (DEMO-01.COL, TELCMDS.FN)._

You can re-play a `.RIP` file that you have locally on your hard disk from any place that allows text variables. After the initial dollar sign (`$`), enter the greater-than symbol (`>`) followed by the filename (with or without the `.RIP` extension), then ending in another dollar sign (`$`). Several examples:

```text
$>MYFILE.RIP$
$>FILE1$
$>FILE1.RIP$$>FILE2.RIP$$>FILE3$
```

The file replays as if it had arrived from the host - with one critical difference: **the data is echoed locally only, never sent to the host**. If the file is a RIPscrip scene, its graphics draw and any mouse fields it defines are created, which is how pop-up dialogs and entire menu systems run without host traffic. The file need not be RIPscrip at all - any text file, ANSI screen, or (in 3.x) flowed article text is legal; see the [Column Text System](3.1-column-text-system.md) for the non-RIPscrip case.

SyncTERM implements the form as a special case checked _before_ text-variable lookup: a leading `>` routes the remainder to `rip_play_scene` (`ripper.c:7967-7970`).

The RIPtel corpus leans on this directive harder than on any other: 34 distinct `$>file$` forms chain the whole demo together - `$>WIPE00.FN$` transition "subroutines", `$>newspapr.rip$` navigation, and the `$<<RETURN>>$` computed-return idiom described under [Templates & Conditionals](5.2-templates-and-conditionals.md#the-3x-macro-layer---name). Filenames are case-insensitive in practice (`$>newspapr.rip$` and `$>NEWSPAPR.RIP$` both appear).

## Local Audio Playback - `$)FILE.WAV$`

_Added in RIPscrip v2.A1._

_Evidence: 2.00a4; HLP._

`$)FILENAME$` plays a local digitized audio file - Microsoft WAVE format as far as the wire is concerned; a terminal using another native format must translate. The file extension itself is unimportant:

```text
$)AUDIOFILE.FIL$
$)TRAIN.WAV$
```

The macro form is the HCL twin of the `1w` ([RIP_PLAY_AUDIO](4.5-audio-files.md#rip_play_audio)) command, and the same playback model applies:

- Audio plays **in the background, asynchronously** - graphics keep drawing and host data keeps arriving while sound plays.
- There is a **single playback channel**: starting a new file terminates whatever is currently playing.
- The wire `1w` filename `$OFF$` silences the current sound. The escaped WAV macro name follows [ordinary filename lookup](#extensions-lookup-and-wav-stop), so use `$RESET(SOUND)$` to stop from HCL.
- If the file does not exist locally, the directive does nothing; hosts deliver audio files ahead of time via block transfer ([6.2](6.2-asset-delivery-and-storage.md)).

See [4.5 Audio Files](4.5-audio-files.md) for the audio format details. Note that RIPtel 3.1's install sets `AUDIO=TRUE` in `RIPSCRIP.INI` and its help advertises "background digitized audio," but the demo corpus itself ships no `.WAV` files and never issues an audio command - the demos are silent. _Evidence: corpus; HLP._

## Local Bitmap Playback - `$<FILE.BMP$`

_Added in RIPscrip v2.A1._

_Evidence: 2.00a4; HLP._

`$<FILENAME.BMP$` places a local bitmap (`.BMP`) file onto the screen through the current **image style** (`1i`, [RIP_IMAGE_STYLE](4.1-jpeg-images.md#rip_image_style)): the bitmap is displayed inside the current image settings and adheres to them. This mode of displaying a BMP file is the only method for showing a BMP via the image-style settings. If no image style definition has been recorded, the bitmap is shown at the maximum size of the current viewport - scaled to fill it entirely.

For the purposes of universality, the bitmap is shown using the current screen's color palette and "auto-dithering" mode. RIPTEL.HLP is explicit that the full flexibility of `RIP_LoadBitmap` (palette modes, clipping options - [RIP_LOAD_BITMAP](4.0-icons-and-bitmaps.md#rip_load_bitmap)) is _not_ available from the macro form; use the wire command when you need it. This directive is provided as a simple method of showing a bitmapped image from within a host command:

```text
$<FILENAME.BMP$
```

Note that this uses the less-than sign, unlike the greater-than sign used for local RIPscrip playback - the opposite angle-bracket marks it as a low-level primitive playback, per the bracket mnemonic above.

## Local JPEG Playback - `$(FILE.JPG$`

_Added in RIPscrip v2.A1._

_Evidence: 2.00a4; HLP; corpus (N2_PHOTO.RIP)._

`$(FILENAME.JPG$` displays a compressed photographic image the same way - through the current image style, or full-viewport when none is recorded. The JPEG file is considered a higher-level object than a raw bitmap, so it uses the parenthesis prefix instead of the angle bracket. JPEG is the only supported photo format in the 3.0 driver:

```text
$(MYFILE.JPG$
```

A companion action variable positions the _next_ image without redefining a style on the wire:

```text
$IMGSTYLE(cur,x0,y0,x1,y1)$
```

where `cur` selects the current screen or offscreen port. This five-argument form resets image flags to zero; add keyword arguments such as ASPECT and NOCLEAR to select flags. See the complete [IMGSTYLE contract](5.1-text-variables.md#imgstyle). Image-style DELETE does not delete this local JPEG in RIPtel 3.1 ([primary derivation](../research/issue-21-image-style.md)). The demo corpus displays its sixteen JPEGs through the wire commands (`1i` + `1p`) rather than the macro form, but the macro and `$IMGSTYLE$` are documented in RIPtel's help as the host-command route to the same machinery.

A [pick-list selection](5.4-popup-lists.md#ordinary-passes-and-transmission) can supply a playback token for a later ordinary pass. A response selected in pass one is eligible in pass two; a response selected in pass two is inserted/skipped with no third pass and no immediate recursive playback. This timing does not alter each prefix’s existing lookup/consumer rules.

## Worked examples per prefix

**`$>file.rip$` - scene playback from a mouse field.** A mouse field whose host command is nothing but a playback variable displays a locally stored dialog scene when clicked - nothing is sent to the host:

```text
!|1M00051E1R2A1100000$>HELPBOX$
```

Clicking the region replays `HELPBOX.RIP` from the connection directory (or the default `ICONS\` directory, or the search path). If `HELPBOX.RIP` itself defines mouse fields - say an "OK" button whose host command is `$PCB$` to paste back the screen area saved earlier - the pop-up is fully interactive without any host round-trip. _Evidence: 2.00a4._

The shipping corpus does exactly this at production scale - a DEMO-01.COL mouse field records a return scene, then plays the weather page, all locally:

```text
!|1M000G7Y8ICC1000000ID=2:$-=RETURN=>NEWSPAPR.RIP$$>TWEATHER.RIP$
```

_Evidence: corpus (DEMO-01.COL)._

**`$(file.JPG$` - image display from a button.** A button that shows a locally cached photograph inside the current image area when clicked:

```text
!|1U0A0A00003200<>View photo<>$(SUNSET.JPG$
```

The image scales into the image area exactly as if the host had issued [RIP_IMAGE](4.1-jpeg-images.md#rip_image) - but with no transmission cost, because `SUNSET.JPG` was delivered earlier by block mode. _Evidence: 2.00a4; HLP._

**`$)FILE.WAV$` - audio playback from a host command.** A host command (or portion of one) that starts background audio:

```text
$)TRAIN.WAV$Now boarding^m
```

The terminal starts `TRAIN.WAV` playing in the background and transmits `Now boarding` plus a carriage return to the host. The wire `$OFF$` sentinel belongs to [RIP_PLAY_AUDIO](4.5-audio-files.md#rip_play_audio); the WAV macro does not recognize it as a stop name. Use `$RESET(SOUND)$` for HCL stop. _Evidence: 2.00a4._

**Chained playback.** Several files can be replayed back-to-back from one command, as in `$>FILE1.RIP$$>FILE2.RIP$$>FILE3$` - useful for assembling a scene from locally cached parts. The corpus's `.RET` return scripts chain a transition wipe and a destination scene the same way (`$>WIPE01.FN$` … `$>TELPORT.FN$`). _Evidence: 2.00a4; corpus (TELDEMOS.RET, MENU.RET)._

**Computed playback (3.x).** With the [macro layer](5.2-templates-and-conditionals.md#the-3x-macro-layer---name), the filename itself can be assembled at run time: `$<<CMD1>>$` expands `<<CMD1>>` to `>TELDEMOS.FN` first, yielding the playback directive `$>TELDEMOS.FN$` - the mechanism behind RIPtel's generic menu scenes. _Evidence: corpus (MENU.MSE)._

## Playback prefixes vs dedicated commands

Same media, different invocation path: the chapter-4 commands live in the RIPscrip **command stream** (the host draws _now_, mid-scene), while the playback prefixes live at the **host-command/macro layer** (the action fires later, when a button or mouse field is clicked, or when a query is processed). The prefix forms also deliberately trade flexibility for brevity - fixed display settings where the commands take parameters.

| Media | Command-stream command | Host-command prefix | Differences |
| --- | --- | --- | --- |
| RIPscrip scene | [RIP_READ_SCENE](5.5-file-transfer-and-queries.md#rip_read_scene) | `$>file.rip$` | Same playback engine; the prefix form is the only one usable from a click |
| BMP bitmap | [RIP_LOAD_BITMAP](4.0-icons-and-bitmaps.md#rip_load_bitmap) / [RIP_LOAD_ICON](4.0-icons-and-bitmaps.md#rip_load_icon) | `$<file.BMP$` | The prefix displays via the image-style area with auto-dithering and the current palette only; the commands offer position, scaling, put modes, palette and transparency flags |
| JPEG image | [RIP_IMAGE](4.1-jpeg-images.md#rip_image) | `$(file.JPG$` | Both display via the current [RIP_IMAGE_STYLE](4.1-jpeg-images.md#rip_image_style) settings |
| WAV audio | [RIP_PLAY_AUDIO](4.5-audio-files.md#rip_play_audio) | `$)FILE.WAV$` | Both start background playback; only the wire filename `$OFF$` has stop-sentinel meaning. A quoted WAV macro name remains a filename; HCL can use RESET(SOUND) |

The corpus shows both paths in production use, split exactly along this line: scene navigation and subroutines fire from clicks via `$>` (34 distinct forms) while mid-scene subroutine calls use `1R` (92 uses in 34 files), and the sixteen demo JPEGs display via the wire commands (`1i` + `1p`) because they are drawn during scene playback, not on click. _Evidence: corpus._
