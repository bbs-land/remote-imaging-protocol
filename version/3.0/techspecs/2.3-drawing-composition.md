# Drawing Composition — 3.0 Delta

[◀ Prev: Bézier Consumer Contract](2.2-bezier-consumer-contract.md) · [Contents](README.md) · [Next: Outline Advances and Cache ▶](2.4-outline-advance-and-cache.md)

The [2.x drawing-composition contract](../../2.0/techspecs/2.3-drawing-composition.md) supplies the five Boolean operations, source selection, filled-border COPY exception, gap matrix and independent pixel vectors. RIPscrip 3.0 inherits that protocol contract. This page states its application to the new/reconstructed primitives; it does not require reproducing an old client's pen API or fixed-width overflow.

N denotes the [normalized current-style border setting](../ripscrip/2.3-shapes-and-fills.md#rip_set_border): a zero input disables it, any nonzero decoded input enables it, and a protected current style rejects the update. The following tables use N0/N1 for that stored Boolean state.

## Primitive roles

| Primitive or contribution | Source and pattern | Operation | N applies? |
| --- | --- | --- | --- |
| PIXEL X | Draw Color, one device pixel | Current W | No |
| POINT j | Draw Color, solid thickness-sized square | Current W, once per covered pixel | No |
| Standalone &, ] | Draw/Back Color using current line pattern and thickness | Current W, including genuine revisits | No |
| Filled I, i, _ interior | Fill/Back Color using current fill pattern | Current W | No |
| Filled I, i, _ outline, including radial parts | Draw Color, solid current thickness | COPY | Yes |
| Filled -, +, [ interior | Fill/Back Color over the polygon region | Current W | No |
| Filled -, +, [ outline | Draw/Back Color using current line pattern and thickness | COPY | Yes |
| K, u, G, o border | Draw Color, solid current thickness | COPY | Yes |
| p, x, poly-polygon border | Draw/Back Color using current line pattern and thickness | COPY | Yes |
| PolyMarker fill, flags 1/3 | Fill/Back Color using current fill pattern | Current W | No |
| PolyMarker stroke, flags 0/1/2 | Draw/Back Color using current line pattern and thickness | Current W | No |

The classification of filled skewed contours as polygon-related borders is an explicit reconstruction: their established contour contract constructs and closes sampled polygons, and the protocol's N rule gives polygon-related borders line patterns. It does not follow from a Windows function name alone. This extends the documented rule to the new family; no recovered specification names these skewed opcodes. [Source/inference ledger](../research/issues-74-76-drawing-contract.md).

The line-pattern custom mask is the requested mask. A backend that cannot express it, or cannot combine it with a wide stroke, needs another rendering path; a fixed DASHDOTDOT substitution or a wide-pen solid fallback is not a protocol definition of the custom pattern. Solid-only primitive borders remain solid even if a backend can render them with a patterned pen.

## Marker Composition

[RIP_PolyMarker](../ripscrip/2.1-lines.md#rip_marker) uses flags 0/2 for a standalone patterned stroke, 3 for an even-odd patterned fill and 1 for both. Both contributions use current W. The marker's pen is selected by its own flags, independently of N and the COPY rule for N-controlled borders.

**Portable overlap rule for flag 1.** For a pen with transparent gaps, apply the fill first throughout its covered interior. Apply the stroke in a second step at each covered stroke sample, using the destination after fill. An unpainted stroke gap leaves the fill result there, or the old destination outside the fill. For an opaque-gap pen the combined presentation chooses a single source at each covered position. Stroke coverage takes precedence over brush coverage, with Draw Color on stroke marks and Back Color in opaque gaps. Elsewhere the fill supplies the source for covered interior pixels. Apply W once to the chosen source and existing destination. This is the portable color contract for the combined call. Exact contour-edge coverage, joins and caps depend on the renderer.

The following sample pixels start with byte value `33`. Use solid Fill Color `55`, Draw Color `0f` and Back Color `aa`. Values are hex and describe already resolved color samples, independent of palette index numbering. Hold flags at 1 and repeat with N=0 or N=1 for the same results.

| Sample | COPY, transparent gaps | XOR, transparent gaps | XOR, opaque gaps |
| --- | --- | --- | --- |
| Interior only | `55` | `66` | `66` |
| Stroke mark overlapping interior | `0f` | `69` | `3c` |
| Line gap overlapping interior | `55` | `66` | `99` |
| Stroke mark outside interior | `0f` | `3c` | `3c` |
| Line gap outside interior | `33` | `33` | `99` |

In the transparent XOR overlap, `33 XOR 55` gives `66`, then `66 XOR 0f` gives `69`. In the opaque XOR overlap, the stroke supplies `0f` and `33 XOR 0f` gives `3c`. Select samples away from joins and use a pen thick enough for stroke coverage to reach the interior. [Source and portable boundary](../research/issue-212-polymarker.md)

## Degeneracy, closure and traversal

Keep the [existing angle/contour construction](2.1-arc-consumer-contract.md) separate from these operations. A radial contour has no area: draw only its border when N1, with solid COPY for I/i, and nothing when N0. A filled full-pie contour containing an internal radius uses the same border contract on that radius. For an even-odd filled polygon, compute holes before filling; do not apply W once per winding. The sampled filled skewed contour may therefore have a hole where an outline-only traversal still revisits pixels.

For ], a sample at parameter 90 and another at 450 are genuine repeated visits when both occur in the preserved normalized span. A single XOR coverage mask must not collapse them into one write. Do not use raw 0..720 as a two-turn example: the previously established normalizer reduces that particular input to one turn. Repeated COPY borders remain idempotent; W does not turn them into repeated XOR borders.

The four N/opaque-gap combinations have exactly the logical phases in the shared table. Internal flag bits and whether RIPtel happened to issue one or two native calls do not add a separate protocol phase. A background fill bit, transparent line gap, opaque line gap and polygon hole are four different cases.

## Backend and historical evidence

X/j's SetPixel/FillRect paths and filled-object native pen/ROP selections are historical evidence. They do not cancel PIXEL's documented Write Mode attribute or N's explicit COPY-border rule. The former [K-specific observations](../research/issue-33-filled-rectangle-borders.md) and [rounded-rectangle observations](../research/issue-38-rounded-rectangle-geometry.md) remain available as client records; their current-mode borders are not the protocol contract. Backend call selection must implement the required color result.

The old arc probe controls pen/ROP services and validates geometry; it does not validate the pixel table. The new checker validates abstract color contributions, thick-point footprints on both destination kinds, repeated visits, fill parity and numeric profile vectors without running RIPtel, GDI, Wine or a desktop renderer. Exact edge pixels, joins/caps and antialiasing are outside these matrices.
