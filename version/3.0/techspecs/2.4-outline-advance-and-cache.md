# Outline Advances and Cached Cursor Width

[◀ Prev: Drawing Composition](2.3-drawing-composition.md) · [Contents](README.md) · [Next: Bitmaps and Masks ▶](3.0-bitmap-mask-delta.md)

This page completes the 3.0 outline-text measurement contract requested in [issue #86](https://github.com/bbs-land/remote-imaging-protocol/issues/86). **The equations and lifecycle below are explicit interoperability choices for this specification.** The recovered documentation does not settle the complete rotation/metric/cache contract, and the original client has distinct rendering and cached-width paths. These rules are not a claim that every RIPtel 3.1 instruction implements them. The [derivation](../research/issue-86-outline-advance-policy.md) separates original evidence, inference and the choices made here.

The adopted [TEXT and TEXT_XY cursor stores](../ripscrip/3.0-text-output-and-fonts.md#rip_text_xy), [spacing adjustment](../ripscrip/3.0-text-output-and-fonts.md#size-rotation-baseline-and-spacing), [unsigned glyph-byte mapping](3.2-fastfont-additions.md#character-bytes-and-raw-font-slots) and [realized horizontal bbox reference](3.2-fastfont-additions.md#global-bounds-and-spacing-reference) remain in force. A rendering advance and a cached X-cursor width are separate quantities.

## Ordinary scalar advance

For a supported outline face, let:

- `a[c]` be the unsigned advance for raw byte code `c` in the font's advance table, in `U > 0` font units per em. Use the selected face's supplied metrics where present, otherwise the family's base metrics. An out-of-range code has advance zero. A valid metric remains usable when its glyph has no ink or its outline record cannot be drawn.
- `Q` be the nominal whole point size, and `H` the selected face's horizontal percentage from its style record: for example, 100 for the base face, 75 for condensed and 125 for wide. Apply `H` once, to the font-unit advance. A percentage is a metric scale, not an instruction to measure raster ink.
- `Dx = trunc(72 * client_width / world_width)` and `Dy = trunc(72 * client_height / world_height)` be effective device DPI, using the current positive frame dimensions. These are unrelated to physical monitor DPI.
- `S` be string rotation and `R` independent absolute character rotation. `P` is the spacing percentage.

Define `round_half_up(x) = floor(x + 1/2)` for nonnegative `x`, and `trunc(x)` as truncation toward zero. Compute each character separately:

```text
r[c] = round_half_up(a[c] * Q * 20 * H / (U * 100))  # 1/1440 inch
w[c] = trunc(r[c] * D / 1440)                        # device units
reference[c] = B if flag 0x0400 is set, else w[c]
gap[c] = trunc((P - 100) * reference[c] / 100)
step[c] = w[c] + gap[c]
```

Use sufficiently wide arithmetic for the products and sum; preserve the rational value until the indicated rounding. `20` converts one point (1/72 inch) into 1/1440-inch units. There is no intermediate 16.16 quantization, unsigned WORD reduction, saturation or floating-point rounding requirement. In particular, do not first add all font-unit advances and then scale the string once.

Select `D` by the **string advance axis**, for every character rotation:

| String rotation `S` | `D` | Device displacement per character | Character rotations `R` |
| --- | --- | --- | --- |
| 0° | `Dx` | `(step[c], 0)` | 0°, 90°, 180°, 270° |
| 90° | `Dy` | `(0, -step[c])` | 0°, 90°, 180°, 270° |
| 180° | `Dx` | `(-step[c], 0)` | 0°, 90°, 180°, 270° |
| 270° | `Dy` | `(0, step[c])` | 0°, 90°, 180°, 270° |

Character rotation changes ink orientation, independently of this scalar. Do not substitute glyph height or project a rotated glyph's ink bounds onto the string axis. `B` is still the realized **horizontal** font-bbox span in device coordinates, after the chosen face/character geometry; it is not the selected string-axis span. Thus character rotation can change spacing with flag `0x0400`, through `B`, without changing `r[c]`. The earlier bbox contract does not promise identical hinting or curved-edge pixels on every renderer; that raster boundary remains unchanged.

Ordinary layout applies **no pair kerning**, including when a font trailer contains kerning pairs. Every character contributes its own final `step[c]`, including the last one. Justification changes the starting placement, not these widths. Synthetic bold, italic, hollow, shadow, underline and strikeout affect ink rather than logical advance; an actual face with different supplied advance metrics uses those metrics. This effects rule and the exact rounding/axis rules are portable policy, not a recovered guarantee about all native synthetic-effect producers.

## Cached outline width is independent

Keep one logical outline metric snapshot per RIP interpreter/drawing context. It is shared across its ports and styles; it is neither a port cursor nor a STYLE-table member. A snapshot contains the realized face/size metric map `r[c]`, **X DPI `Dx` at preparation**, spacing `P` and flag `0x0400`, and realized horizontal span `B`. It must remain available even when the rendering backend discards its glyph bitmaps.

For cached measurement, use the preceding per-character equations with **the snapshot's `Dx` for every string direction** and its stored spacing/bbox values. Read every input byte as an unsigned code, including `0x80..0xff`; no code-page conversion or sign extension is performed. The text's existing framing/expansion rules determine the input byte string; NUL terminates it where a C-string interface is used.

```text
Wcache(text, invalid snapshot) = 0
Wcache(text, valid snapshot) = sum(step[c] for each input byte c)
Woutline = s16(Wcache)
s16(n) = ((n + 32768) mod 65536) - 32768
```

Only the final `s16` handoff is required by the adopted cursor-store contract. It does not narrow each metric or the accumulator, and does not limit rendered positions. **All accepted strings are processed finitely using their full length.** There is no new 255-byte limit, byte-sized loop index, silent 255-byte truncation or required native loop failure. Existing command/expansion limits still apply; resource rejection must be nonfatal and must not partially commit a text call.

For example, a vertical string can render with `Dy` yet update the stored X cursor by an X-DPI cached width. That distinction is intentional: string displacement and the adopted stored cursor are different protocol quantities. Classic fonts 1–10 retain their classic width service. Classic font-zero TEXT_XY uses `Woutline` from the last outline snapshot; selecting classic zero does not realize an outline font.

## Snapshot lifecycle

These lifetime and failure rules are **explicit protocol policy**; the recovered source documentation does not establish a complete historical cache guarantee.

| Event | Logical snapshot |
| --- | --- |
| New interpreter or full graphics/drawing reset | Invalid; cached width is zero |
| Selecting an outline face/size, changing STYLE, switching ports or changing the world/client frame | Retain the last snapshot; selection alone does not prepare metrics |
| Accepted, nonempty outline TEXT/TEXT_XY successfully prepares its requested metrics | Atomically replace every snapshot field using the call's current settings, before measuring its cursor width |
| Outline font lookup, validation or metric preparation fails | Retain the last successful snapshot, or remain invalid if none exists |
| Metrics succeed but no ink is produced (blank glyph, clipping, or a later raster/presentation failure) | Keep the newly committed snapshot; perform the adopted accepted-call cursor update |
| Empty text or disabled viewport | No preparation or cursor/cache change |
| Classic TEXT/TEXT_XY, cursor movement, STYLE/PORT reset or viewport erase | Retain the snapshot; classic zero can read it without changing it |

A full drawing reset is distinct from resetting an individual STYLE or PORT. Failure must not combine a new DPI/spacing value with old face metrics. A failed accepted outline call measures its text against the previous snapshot; an invalid snapshot contributes zero. Subsequent successful outline text recomputes from the new frame and style. Backend bitmap-cache invalidation does not itself invalidate this logical snapshot. No GUI prompt, font error dialog or ink production is required to establish a width.

## Distinguishing vectors

The font inputs below are original MARIN.RFF metrics (`U=1000`, `F=556`, raw byte `0x80=167`, `0xff=1000`). **The outputs are vectors for the stated policy**, not new observations from executing RIPtel. Use base face `H=100` and `P=100` unless stated otherwise.

| Input | Intermediate `r[c]` | Result |
| --- | --- | --- |
| `F`, 90 points, `Dx=72` | `round_half_up(1000.8)=1001` | `w=50` |
| `F`, 90 points, condensed `H=75`, `Dx=72` | `round_half_up(750.6)=751` | `w=37` |
| `FF`, 10 points, `Dx=36` | `111` per byte | `2+2=4`, rather than whole-string conversion `trunc(222*36/1440)=5` |
| One byte `0x80`, 90 points, `Dx=72` | `301` | `15`; an unsigned code, not a negative missing-glyph code |
| One byte `0xff`, 90 points, `Dx=72` | `1800` | `90` |
| `F`, 90 points, `Dx=72`, `Dy=36`, any `R` | `1001` | Ordinary scalar 50 for `S=0°/180°`, 25 for `S=90°/270°`; cached width 50 in all four directions |
| `F`, 90 points, `Dx=72`, `P=125`, ordinary reference | `1001` | `50 + trunc(25*50/100) = 62` |
| Same, flag `0x0400`, realized `B=102` | `1001` | `50 + trunc(25*102/100) = 75` |
| 260 copies of `F`, 90 points, `Dx=72` | `1001` per byte | Finite `Wcache=13000`, `Woutline=13000` |
| 700 copies of `F`, same settings | `1001` per byte | `Wcache=35000`, final `Woutline=-30536`; no internal wrap requirement |

A blank or clipped `F` keeps the same metric. A valid space with no ink likewise retains its own advance. For missing codes, `w=0`; flag `0x0400` can still contribute the existing bbox-based extra gap when `P` differs from 100.

For cursor examples, take viewport origin `(5,7)`, supplied TEXT_XY anchor `(100,80)` and prior cursor `(300,400)`. The cached text is one `F`:

| Situation | Outline TEXT_XY cursor | Classic font-zero TEXT_XY cursor |
| --- | --- | --- |
| Cold snapshot; outline preparation fails, matching frame | `(105,87)` | `(105,87)` |
| Last successful snapshot: 90 points, `Dx=72`, `P=100`; current frame still matching | `(155,87)` | `(155,87)` |
| World/client ratio becomes 2:1 on both axes; attempted outline preparation fails | `(105,47)` (converted anchor plus retained 50) | `(155,87)` (raw anchor plus retained 50) |
| Same new frame; successful outline preparation commits `Dx=36` | `(80,47)` (converted anchor plus 25) | `(130,87)` when called afterward (raw anchor plus 25) |

The cold classic-zero example needs no outline call beforehand. In the failure rows, a newly selected `P=125` does not alter the retained `P=100` snapshot. In the success rows, clipping every glyph does not change the result. A following TEXT from `(300,400)` with retained width 50 stores `(350,400)`, even for a vertical string; with an invalid snapshot after failed outline preparation it stores `(300,400)`. Classic nonzero TEXT still uses its own metric. These vectors preserve the previously adopted origin/conversion/font-zero cursor branches without treating the earlier controlled widths 13/37 as real font measurements.
