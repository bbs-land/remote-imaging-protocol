## Original stages and first native checkpoint

Original full host entry **0x4ab3e** first runs angle preprocessing0x4c213 and then delimiter scanner **0x4ad51–0x4ae9d**. The scanner searches the complete source for syntactically recognized bracket directives; it has **no ESC state**, no special-key whitelist and no preceding-backslash gate. A lone `[` or `[` followed by non-Mega character is not a complete template directive and remains ordinary text. A bracket followed by a valid Mega slot character but no proper closing delimiter can call diagnostic **0x38e47** with `Invalid MegaNum` at0x4adfa, then continue scanning and ultimately pass the unrecognized source through. It is not atomic fail-before-execution validation.

Original response executor **0x4acd9** runs ordinary expansion0x4b0e4 twice: first flags masked0xff5f (no control/backslash conversion), then full flags. Actual two-byte control conversion is **0x4b394–0x4b445**. It recognizes caret/backquote only with a non-NUL next byte and flag0x20 set. A doubled _same_ prefix removes one byte and skips the resulting literal. Otherwise original CRT alphabet classification (`ctype &0x103`) uppercases letters and subtracts0x40; nonalphabetic ASCII bytes0x5b..0x5f also subtract0x40. All other pairs remain unchanged. Therefore uppercase/lowercase A..Z map1..26; `[`, backslash, `]`, `_` map27/28/29/31; `^^` is literal caret while backquote+caret maps30. `^@` does **not** produce NUL; `^?` remains literal, not DEL. Trailing caret/backquote remains literal. This contradicts the inherited NUL row and unlimited character-minus-@ formula.

The DLL’s default CRT alphabet table is a real shipped source: pointer at **RVA0x87908** initially points to **0x10087912** (data file offsets =RVA−0x1a00), multibyte max0x87b14=1, locale0x88060=0. Under mask0x103 its ASCII alphabet membership is exactly A..Z/a..z. Original uppercase **0x68b20** takes its ASCII/default-locale fast path. The native extension restores that exact original table pointer and original uppercase prologue during these tests, rather than relying on the macro fixture’s C-locale substitutes; it restores prior hooks afterwards. This establishes ASCII behavior in the shipping default locale, not every platform locale’s classification of non-ASCII bytes.

Initial exploratory full-host captures confirm `^[[A` and backquote+`[[A` →hex **1b5b41**, `^[[Z`→**1b5b5a**, lone raw `[`→**5b**, trailing caret/backquote→**5e/60**, `^?`→**5e3f**, lowercase `^m`→**0d**, and `^@`→**5e40**. The three requested unclosed letter-key forms report one nonfatal incomplete-template diagnostic, but still transmit their full byte sequence. General `^[[0m`/`^[[31m` also pass as ESC sequences; unlisted key Z does not reject. There is no atomic special-key exception.

With template3=`THREE`, templateA(10)=`TEN`: `^[[A]`→ESC+`TEN`, raw ESC+`[A]`→ESC+`TEN`, and `^[x[3]`→ESC+`xTHREE`. Thus an ESC does not suppress later template recognition, and template syntax is resolved **before** caret becomes ESC. `[3]` invokes template3. `\[3]` also invokes template3: quoting does not hide a complete directive from the earlier segmentation scan. `\[` yields a literal `[`, and a raw lone `[` already does too. A variable BRACKET=`[3]`, expanded via `$BRACKET$` after segmentation, transmits literal `[3]`: returned dollar text is not restarted through bracket segmentation. `x[A:]TAIL` transmits x and stores TAIL as templateA. `^[[A]TAIL` transmits ESC+TEN because marker-free composition uses that template rather than appending the remainder. Both examples follow #6’s original template engine, not an added rewrite.
