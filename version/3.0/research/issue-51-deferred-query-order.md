## Event-path and native checkpoint

The anticipated loop does not exist in the recovered shipping event path. Original `RIP_ProcessEvent` **0x43f5** requires instance magic0x9df3, initialized context+0x5e and matching HWND+0x66; these are supplied. Left-down **0x52e7–0x537d** updates the mouse point, locks mouse/button/style, scans only mouse fields backwards, calls **0xe749** to test each field rectangle, and on a hit invokes **0x2c424**. An empty or missed field table goes directly to unlock/return. It never visits PORT/TW records or floating query pointers. Left-up **0x537d–0x5405** only completes a previously hit field; otherwise it clears button-down state and returns. Movement **0x5283–0x52e7** handles held fields and original hover helper **0x4035–0x41b8**, whose two passes execute only mouse-system+0x20 exit and+0x1c entry strings. Right/middle down/up merely set their mouse-state flags. There is no dormant numbered/floating click loop gated by table activation, protection or current selection on these branches.
