## Original flags and ordering checkpoint

Physical dispatch **slot88**, level1 `b`, selects **0xc569**, argument types **XY,XY,XY,XY,mega1,mega1,mega2,mega2,mega4**, followed by filename. Handler reads flags at decoded argument6 and rejects unsigned values **>63** at **0xc5e6**, before scratch/name processing or lookup, reporting `Invalid flags parameter`. Thus bit32 is also accepted/defined; bits64 and above are rejected, not masked off. There is no alternative field split that makes canonical0G mean something else.

Initial draw requests to original **0x4a410** at0xc957 use bit2→palette mode1(adopt) versus2(current), bit4→dither boolean and bit8→translated transparency key versus−1. A nonzero far-corner pair selects fit/stretch1; both far coordinates zero select natural size/stretch0. The only downstream full-flags tests after this draw are bit1 duplication at **0xc9d2**, then bit16 wallpaper at **0xca99** with bit32 passed at **0xcad3–0xcae4**. Bit16 is not passed to the file reader, remapper or initial image scaler and does not toggle those requests.

Bit16 calls **imageWallpaper0x3ea2e** with (a) the **renderer-returned initial image rectangle**, (b) the **then-current port’s viewport** from record+0x3a..0x46, (c) low-word flags&32. Original geometry reconciliation **0x3f0a6** clips source far bounds to viewport far bounds and rejects nonpositive/irreconcilable extents; it does not reload a file. Original tile generator **0x3ea2e–0x3f0a5** uses same-DC **BitBlt SRCCOPY0xcc0020**, explicitly sets **ROP2=13/COPY**, repeats the seed horizontally, then repeats rows vertically. With bit32 absent rows align. With bit32 present alternate rows are offset left by **floor(tile_device_width/2)** relative to the seed row. Tile dimensions/phase come from the already-drawn device rectangle; no additional world scaling, palette adoption, dithering, transparency test or per-repeat requested ROP occurs. Existing background retained by the initial color key is part of the copied tile. This matches the independently traced image-style wallpaper helper from #21.

Duplication occurs **before wallpaper**, so flag1 captures the initial composited rectangle rather than the full wallpapered viewport. Explicit duplicate==current skips duplication but not wallpaper. Duplicate0 calls original GET_IMAGE helper0x2866; the #42 derivation proves its assigned-current deletion can change current to0. The bitmap handler re-reads current/viewport after that helper, so wallpaper uses the resulting current port, not a saved original selection. Native controlled-helper retargeting confirms the caller behavior without claiming to re-test GET_IMAGE itself. Explicit duplicate deletion failure returns at0xca35 before wallpaper; failed creation takes0xca6e→0xca99 and still attempts wallpaper. Decoder/render failure instead enters placeholder/cleanup and returns through **0xc9c3→0xcb31**, before duplication/wallpaper. A partially read static branch had initially suggested fallthrough after failure; the native capture and complete cleanup branch reject that reading.

## Native matrix and wallpaper geometry

`run/riptel-bitmap-probe DLL` now passes **378,264 checks** on FreeBSD15.1/clang19.1.7, native -m32. The original handler executes all64 accepted flags×five put modes×natural/explicit size×duplicate choices0/current2/7/35/36, capturing exact initial dither/palette/stretch/key/ROP/geometry and post-draw requests/order. All64..4095 values reject with exact `Invalid flags parameter` before lookup/draw/duplication/wallpaper; this covers either two-character radix domain. Failure guards and a controlled clipboard-current change have separate cases.

For that routing matrix, original renderer entry is a controlled observer at0x4a410; wallpaper0x3ea2e, clipboard0x2866, explicit duplicate creation0x3326f/deletion0x33112/copy0x134d0 are separate observed boundaries. They establish handler flags/ordering, not actual duplicate pixels. Existing #8 services still control macro/name/coordinate/viewport application for those routing tests. Actual renderer bytes and wallpaper bytes are restored for the following checks. No original parser/flags/branch code is replaced.

The original wallpaper helper and rectangle reconciler then run over **1,400 nondegenerate tile/phase grids**: widths1..7, heights1..5, five X origins, four Y origins, plain/staggered rows, on a12×10 owned RAM surface. Exact label patterns confirm phase `(x-left + odd_row*floor(width/2)) mod width`, `(y-top) mod height`, with odd/even rows measured relative to the seed row in either direction. Additional nonzero viewport and clipped-right source cases retain all outside pixels and repeat the clipped seed width. Zero-width source reports reconciliation errors before any loop/blit.

Controlled wallpaper services are **SetRect IAT0x96618**, **OffsetRect0x96610**, **SetROP2 0x96408** and same-DC **BitBlt0x963e4**, plus the existing invalidation/UI/viewport hooks. The RAM BitBlt snapshots its source and applies the owned viewport clip; it records that every original request is COPY with bounded positive geometry. This is an original-instruction geometry/copy oracle, not Windows GDI stretch/palette raster parity.

Finally, full original **wire handler→BMP reader→renderer→wallpaper** runs for allfive put modes, natural/explicit size, with/without color key and without wallpaper/with16/with16+32. One named file is opened each time. Wallpaper output equals repetition of the actual first-draw tile, including pre-existing background at transparent pixels and the initial non-COPY operation. It neither re-opens the file nor re-composites each destination against that destination’s prior background. Palette/dither flag independence is proved at the original caller argument boundary; earlier #8 renderer controls and limits remain explicit.

Harness failures were separated from client observations: the first flag16 routing run lacked the SetRect import fixture, fixed by installing the existing service before the matrix; the first nonzero-viewport check lacked destination clipping in the RAM BitBlt fixture, fixed there. Neither is a shipping-client failure. A scoped GDB build diagnosed the former and was removed on exit; native wrappers disable cores and remove task build directories. No GUI/Wine/audio/actual asset writes.

Previous scene commands include world `fZKQO`=1280×960 and creation/activation of port1; the initial box is in **world coordinates**, not a guaranteed640×34 device-pixel band. Original **strip6.bmp**,5724 bytes, SHA256 `6e09793c251a442cc0a3cb2663c6aec496787536cc716d4d305be8d50c053ac6`, is a320×17 8-bit BMP. The inherited “stretched header band” description misses the wallpaper step and confuses world and device dimensions.
