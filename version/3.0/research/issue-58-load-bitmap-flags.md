## Original flags and ordering checkpoint

Physical dispatch **slot 88**, level 1 `b`, selects **0xc569**, argument types **XY,XY,XY,XY,mega1,mega1,mega2,mega2,mega4**, followed by filename. Handler reads flags at decoded argument 6 and rejects unsigned values **>63** at **0xc5e6**, before scratch/name processing or lookup, reporting `Invalid flags parameter`. Thus bit 32 is also accepted/defined; bits 64 and above are rejected, not masked off. There is no alternative field split that makes canonical 0G mean something else.

Initial draw requests to original **0x4a410** at 0xc957 use bit 2→palette mode 1(adopt) versus 2(current), bit 4→dither boolean and bit 8→translated transparency key versus−1. A nonzero far-corner pair selects fit/stretch 1; both far coordinates zero select natural size/stretch 0. The only downstream full-flags tests after this draw are bit 1 duplication at **0xc9d2**, then bit 16 wallpaper at **0xca99** with bit 32 passed at **0xcad3–0xcae4**. Bit 16 is not passed to the file reader, remapper or initial image scaler and does not toggle those requests.

Bit 16 calls **imageWallpaper 0x3ea2e** with (a) the **renderer-returned initial image rectangle**, (b) the **then-current port’s viewport** from record+0x3a..0x46, (c) low-word flags&32. Original geometry reconciliation **0x3f0a6** clips source far bounds to viewport far bounds and rejects nonpositive/irreconcilable extents; it does not reload a file. Original tile generator **0x3ea2e–0x3f0a5** uses same-DC **BitBlt SRCCOPY 0xcc0020**, explicitly sets **ROP2=13/COPY**, repeats the seed horizontally, then repeats rows vertically. With bit 32 absent rows align. With bit 32 present alternate rows are offset left by **floor(tile_device_width/2)** relative to the seed row. Tile dimensions/phase come from the already-drawn device rectangle; no additional world scaling, palette adoption, dithering, transparency test or per-repeat requested ROP occurs. Existing background retained by the initial color key is part of the copied tile. This matches the independently traced image-style wallpaper helper from #21.

Duplication occurs **before wallpaper**, so flag 1 captures the initial composited rectangle rather than the full wallpapered viewport. Explicit duplicate==current skips duplication but not wallpaper. Duplicate 0 calls original GET_IMAGE helper 0x2866; the #42 derivation proves its assigned-current deletion can change current to 0. The bitmap handler re-reads current/viewport after that helper, so wallpaper uses the resulting current port, not a saved original selection. Native controlled-helper retargeting confirms the caller behavior without claiming to re-test GET_IMAGE itself. Explicit duplicate deletion failure returns at 0xca35 before wallpaper; failed creation takes 0xca6e→0xca99 and still attempts wallpaper. Decoder/render failure instead enters placeholder/cleanup and returns through **0xc9c3→0xcb31**, before duplication/wallpaper. A partially read static branch had initially suggested fallthrough after failure; the native capture and complete cleanup branch reject that reading.
