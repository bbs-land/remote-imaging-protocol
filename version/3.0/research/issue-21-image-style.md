## First original entry-point trace

Dispatch physical slot **98**, level-1 i, is IMAGE_STYLE **0xc39a**, arguments four XY fields, mega4 flags and 12 reserved characters. Physical slot **103**, level-1 p, is IMAGE **0xc2c6**, one mega4 reserved field and filename. IMGSTYLE original registration **0x26c77–0x26c82** binds callback **0x2f1be**.

IMAGE_STYLE accepts flags **0..63**, normalizes coordinate order through **0x3112e**, converts both corners through **0x31084**, and stores a SetRect at current 0x78-byte port record **+0x4a** with both far coordinates **incremented by one**. Flags are a word at **+0x5a**. Adjacent synchronization functions **0x34488 / 0x34489** are one-byte RETs; never apply five-byte hooks to both. Verify all-zero area behavior after this +1 storage conversion rather than assuming the inherited disable description is literally implemented.

IMGSTYLE has more surface than the HLP synopsis: zero/one argument **queries** image rectangle and flags, formatting **`%hd:%hd:%hd:%hd:%hd`** after reverse coordinate conversion **0x310f2**. First target argument is parsed by **0x98fc**, with CUR (-1) resolving current; **0x338bc** checks defined and port+0x17 bit 2 rejects a type that still needs identification. Undefined/invalid-type branch returns string constant **0x7a100** (previous issues identify `-1`) rather than defining a port. Invalid selector -5 sets variable error.

Set form requires at least **five** arguments. The local flag accumulator is initialized to **zero** at **0x2f1d1**; additional arguments starting at index 5 recognize case-insensitive **ASPECT (1), DELETE (2), NOCLEAR (4), USEPAL (8)** via **0x2f37a–0x2f3e8**; an unknown extra sets variable error before setting. It checks target protection **0x33821**, temporarily selects the target with **0x3393c**, invokes original IMAGE_STYLE, then restores previous current port. Thus the premise that IMGSTYLE has no flags facility is incomplete; native default/target/protection tests are required before documenting this.

IMAGE handler expands its filename then invokes **0x3880e(context,filename,1)**. The latter checks current port state, tests stored image right/bottom at +0x52/+0x56 for zero and normally calls **0x3815f(context,filename,1,retrieve)**. A zero stored right or bottom instead reaches **0x383b0** placeholder/drawing path without ordinary JPEG display. Because IMAGE_STYLE increments endpoints, an all-zero command initially appears to store right=bottom=1; this is a lead to verify, not a published conclusion.

Common image presentation **0x3815f** looks up JPG through **0x3f80e**, calls **0xf363** to classify the file, uses image area or viewport according to **0x34385**, then reaches **0x37fb5** for actual JPEG processing. Its success tail tests image flag **0x10** (16) and calls **0x3f12f**; the effect remains to trace. No image deletion policy is established merely by this entry-point walk. Trace final file operation and actual clear/margin consumers.

## Downstream static leads (native validation pending)

Port record +0x17 bit 2 is **viewport disabled**, not an offscreen-port type: viewport setter **0x33cc6** sets it for all-zero viewport coordinates (**0x33cf9–0x33d1d**) and clears it for a nonempty rectangle (**0x33d6b–0x33d76**). Thus IMGSTYLE’s early gate must be tested as undefined/disabled-viewport, not assumed screen-only. Original definition/protection/current-selection helpers are **0x338bc / 0x33821 / 0x3393c**; the last switches existing offscreen DCs directly and can default an undefined target, but IMGSTYLE’s earlier definition gate should prevent that path. Keep these original helpers in its probe.

Original JPEG orchestrator **0x37fb5** reads dimensions through **0x57e80**, sets per-image state context+0x56 **+0x0c** to `!(flags & 4)` through **0x296e0**, sets **+0x10** to ASPECT through **0x29700**, and sets +0x14 to zero via **0x29770**. It rejects zero `abs(right-left-1)` or `abs(bottom-top-1)`, otherwise fits/draws through **0x4d14d / 0x45d60**. It tests only bits 1 and 4 here; no DELETE/USEPAL consumer has yet been identified. The native all-zero-style test must include this one-pixel extent rejection; storing right/bottom=1 alone does not prove a visible one-pixel image.

The high-level ASPECT path calls **0x4d14d** with **clear=0, aspect=1** at **0x38088–0x3809b**. Argument order is `(context,input_rect,output_rect,width,height,clear,aspect)`; the final `push 1` is the seventh/aspect parameter, not the sixth/clear parameter. An early lead incorrectly labeled it an unconditional clear; tracing the callee’s +0x1c/+0x20 arguments corrected that before publication. Rectangle helper **0x4d14d** calls **0x4d256** only when clear equals 1; **0x4d256** obtains stock object **4 (BLACK_BRUSH)** and calls **FillRect** through IAT **0x9667c**. It does not use the current background brush/pen ROP. Later JPEG preparation **0x29880** calls **0x4d14d** with clear/aspect from per-image state +0x0c/+0x10 at **0x29919–0x29942**. Native captures must establish exact fill counts/rectangles and whether NOCLEAR leaves margins untouched rather than blackening them.

Lower original file/JPEG wrapper **0x45d60** writes rectangle to per-image state through **0x29720**, opens its file via **0x68f90**, initializes JPEG error/decompressor services **0x57fb0 / 0x57720 / 0x4aa40**, loops the JPEG state dispatcher **0x29c30**, closes through **0x68ec0** and destroys through **0x57790**. These loops contain no direct unlink. Original scan-line consumer **0x29ad0** passes **SRCCOPY (0xcc0020)** to StretchDIBits at **0x29bba–0x29bf0**. The file/decoder boundary may be controlled for state/effect tests while preserving preparation/fill/scan-line consumers; do not pretend a stubbed decoder proves JPEG pixel parity.

The exported client entry **RIP_ShowImageWithCurrentStyle 0x69d8** calls **0x3815f(context,name,0,0)**, whereas explicit IMAGE uses **0x3880e** then **0x3815f(context,name,1,retrieve)**. Original unpacked client imports ShowImage at VA **0x45b820**; post-transfer path from issue #19 should be revisited for any separate received-file deletion flag. The driver stores image flag 2 but its direct +0x5a consumers identified so far test only **1,4,16,32**; do not claim bit 2 actually deletes until a complete downstream/client audit establishes it. Flag 16 invokes **0x3f12f**, which redraws using **0x3ea2e** and tests bit 32; it is not itself an unlink helper.

Reset producers identified: SOFT **0x16220** stores image rectangle all **-1** and flags zero on the **current port** at **0x16298–0x162eb** before later selection/reset work. Port-system initializer **0x33d82** initializes record zero image rectangle all -1 and flags zero. Other image-flag writes occur **0x1671b / 0x169d1** (outer resets), **0x22616 / 0x2c63d** (other state consumers), **0x47441** (header/segment path). Trace exact outer gates and effects on protected/surviving ports in native tests rather than assuming full-viewport values or all-port resets.

## Native style checkpoint

New `run/riptel-image-probe DLL` passes **401 original-instruction checks** on FreeBSD 15.1 amd64 / clang 19.1.7. It SHA-verifies the unchanged DLL, disables core dumps, compiles in a task-owned temporary directory and removes the build through its EXIT trap. No GUI or real filesystem mutation runs.

Preserved: original IMAGE_STYLE **0xc39a**, IMGSTYLE **0x2f1be**, selector parsing **0x98fc**, definition/protection/current selection **0x338bc / 0x33821 / 0x3393c**, coordinate normalization/conversion and original adjacent synchronization RETs. Controlled host/display hooks: **0x45038 / 0x18cf6 / 0x18bf7 / 0x343e4 / 0x342ad / 0x34319 / 0x13c69 / 0xe6e9**; report **0x38e47**, memory string/format/decimal primitives **0x65431 / 0x655e2 / 0x65604 / 0x68440**, ASCII class table **0x87908**, SetRect IAT **0x96618**. World/device fixture is 1280×960 / 640×480. Original registration push bytes confirm callback identity before probing.

Verified all flags 0–63 accepted, 64 rejected unchanged with one report; corner ordering and far endpoint+1; all-zero command stores (0,0,1,1). Every IMGSTYLE keyword combination 0–15 replaces previous flags; no keywords resets them to zero, not retention. Literal numeric extra `3` is rejected as unknown keyword. Setter temporarily selects a valid target and restores previous current/DC. Both screen type 1 and offscreen type 4 are valid; CUR is not screen-only. Undefined slot 5 yields `-1`, no variable error and remains undefined. Invalid slot 36 sets variable error.

Original viewport-disabled bit 2 at port+0x17 yields `-1` for **getter and setter**, without variable error. A protected but enabled target still allows the getter; setter returns no text and does not change rectangle/flags. A writable enabled target is modified. Query of device rectangle (10,20,111,121) at scale 2 returns **`20:40:222:242:15`**: stored far extents are converted directly, not decremented back to original inclusive input (220,240). Record this query discrepancy if documenting the newly recovered getter.

First probe failure was an inconsistent screen-port DC fixture: current logical screen port 5 still uses port zero’s DC, whereas an offscreen port uses its own DC. Preserving original selection exposed that error; fixing fixture DC initialization resolved it. A second expectation mistakenly treated a disabled-viewport setter as NULL; the original early gate returns `-1` as the getter does. Both corrections are reflected in assertions, not classified as driver failures.

Expanded image probe passes **6,545 checks**. It preserves **0x37fb5** JPEG orchestration, **0x45d60** file/decompressor lifecycle, **0x29880** decoded-image preparation, **0x4d14d / 0x4d256 / 0x4d060 / 0x4d1fe** rectangle fitting/clear operations, **0x1525d** coordinate-map generation and **0x29ad0** scan-line painting. Controlled decoded images are 10×5 and 5×10, style rectangle (10,20,110,120); all **64 flag combinations** execute for both aspect orientations.

The JPEG state dispatcher **0x29c30** is replaced with a single scripted decoded-image phase that supplies width/height, invokes original preparation **0x29880**, supplies one controlled byte row, invokes original scan-line consumer **0x29ad0**, then reports state-machine completion. This executes geometry and GDI consumers, not actual JPEG entropy/color decoding. Map/line buffers are owned static arrays, not leaks. IAT captures: stock brush **0x9640c**, FillRect **0x9667c**, OffsetRect **0x96610**, RealizePalette **0x963e0**, DeleteFileA **0x965dc**, StretchDIBits **0x96454**.

Observed fills:

| Flags affecting geometry/clear | Wide image fill | Tall image fill |
| --- | --- | --- |
| Neither ASPECT nor NOCLEAR | (10,20,110,120), one black FillRect | Same |
| ASPECT, no NOCLEAR | (10,45,110,95), one black FillRect | (35,20,85,120), one black FillRect |

**ASPECT margins are not blacked out by this path.** High-level fitting supplies a fitted image rectangle to the lower wrapper; the later black clear covers only that fitted rectangle. Areas outside it retain prior contents, including under NOCLEAR. Other flag bits do not change these calls. Every actual row is painted through StretchDIBits with explicit **SRCCOPY 0xcc0020**, irrespective of the current vector write-mode convention. The stock BLACK_BRUSH selection also disproves an inherited current-background-color clear description for this implementation.

Microsoft’s [FillRect contract](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-fillrect) describes filling with the supplied brush and exclusion of right/bottom borders; its [StretchDIBits contract](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-stretchdibits) defines the explicit raster-operation parameter. These current API documents describe the captured boundary, not a claim that the 1997 driver supported modern JPEG/PNG passthrough or exact host pixel parity. The native fixture checks original geometry/brush/ROP arguments without substituting its own fitting math.

Original file/JPEG wrapper opens and closes the controlled image exactly once and never calls DeleteFileA for any flag combination, including DELETE. This is native proof for that wrapper path; complete presentation/disabled-area and client post-transfer entry points remain to test before resolving the issue’s deletion question. The first scripted decoder return used status 0 and caused another original-loop iteration; original status 1 means complete. Correcting the service status fixed the fixture, with no driver failure inferred.

Client post-transfer cleanup lead: EXE thunk **0x36f82** jumps through IAT **0x45b838** to **RIP_AddTempFile**, not a direct delete routine. EXE **0x206eb–0x206fe** tests transfer-flag global **0x44c0b0** bit 1 and registers the completed filename for later cleanup. Original block-mode handler **0x24b4e** sends message 0x4c9 with the command’s fourth decoded field shifted to the high word, OR’d with file type, at **0x24f58–0x24f6b** and analogous protocol branches. This is separate transfer state, not an image-style flag read. Trace the eventual temp cleanup and native presentation/encoded reception before claiming all delivered-file behavior.

## Full presentation and zero-area checkpoint

Expanded probe now passes **62,449 checks**, preserving common presentation **0x3815f**, explicit image wrapper **0x3880e**, client export **0x69d8**, original JPEG orchestration/lifecycle/preparation/scan-line consumers. For every flag 0–63 it tests both entry paths with a normal area, a wire all-zero IMAGE_STYLE area and the distinct raw-zero state sentinel. Additional controlled boundaries are resource lookup **0x3f80e**, existence **0x758e0**, JPEG signature classification **0xf363**, placeholder graphics **0x383b0**, diagnostic notification **0x41b8** and post-display area redraw geometry **0x3ea2e**; string copy/length wrappers **0x68910 / 0x654a8** are ordinary host primitives. Original rectangle/state decisions and calls remain unchanged. Placeholder drawing is counted, not rendered or credited with decoder behavior.

**The all-zero IMAGE_STYLE command does not disable JPEG display in this driver.** It stores (0,0,1,1). Common presentation subtracts one from the stored far edges before calling **0x37fb5**; that helper subtracts another one for its nonzero-size test and rectangle setup. The zero resulting far coordinates become -1 in the low-level rectangle, then original preparation **0x29880** substitutes physical port-system device width/height for nonpositive far coordinates. Native full-entry tests open/decode/prepare/paint once, rather than ignoring the image. The initial expectation of one-pixel rejection was overturned by executing the complete caller chain; neither endpoint storage nor the low-level helper alone settled the outcome.

A distinct raw record rectangle **(0,0,0,0)** causes explicit wrapper **0x3880e** to issue a diagnostic notification and skip lookup/presentation, via **0x343b6**. It is not what the all-zero wire command stores. The client export bypasses that explicit wrapper and still presents through full-viewport fallback for raw-zero records. Across both entry paths and all three area states, **no image-style flag causes a DeleteFileA call** in the tested original presentation tree, including flag 2. Native tests trap deletion and preserve original file close/format and presentation decisions. Client post-transfer/encoded-stream cleanup still requires its own audit before claiming all received-file effects.

The captured redraw-helper flag needed signed/unsigned **low-word** handling: original 0x3f12f uses AX for bit 32 and leaves unrelated high argument bits stale. Masking the controlled helper’s argument to 16 bits fixed its fixture assertion. This is an ABI-boundary correction, not a shipped image-flag defect.

## Original outer reset/header checkpoint

Expanded native probe passes **62,507 checks**. It preserves original SOFT **0x16220**, HARD **0x16665**, port deletion/destruction/initialization **0x33112 / 0x3302c / 0x3326f**, protection/unprotection **0x33821 / 0x3378a**, current selection **0x3393c**, port-zero initializer **0x33d82**, viewport setters **0x33cc6 / 0x33df3**, actual RESET_WINDOWS **0x1f2f9**, and HEADER **0x1cae1 / 0x1774f / 0x1799e**. Unrelated reset families and host/GDI services are controlled at the exact addresses catalogued in `reset_checks()` in the committed probe; these fixtures establish image/port lifecycle, not every other reset subsystem. Reset fixtures own all dependent context objects and style arrays.

SOFT resets the **old current port's** image rectangle to all -1 and flags to zero before selecting/resetting anything else, even if that port is protected. The original port-system initializer independently resets **port zero** to the same defaults. A different protected surviving port retains its image rectangle and flags. Under SOFT keep-ports=0, an unprotected nonzero port is deleted; under keep-ports=1 it survives. These cases include old current screen and offscreen ports.

Actual RESET_WINDOWS calls SOFT with `(keep_ports=0, clear=1, update=1)` and ends on port zero. Native tests start with current zero or protected port five, also protected port six and unprotected port seven: zero and the old current receive image defaults; protected noncurrent ports retain their style; seven disappears. HEADER flag 2 produces the same drawing-reset behavior. HEADER flag 0 leaves the image state unchanged. HEADER flag 1 performs HARD: nonzero ports disappear despite protection, and port zero has default image state. Thus “reset all image areas in every surviving port” is incorrect. The all-minus-one marker means **use the viewport at display time**, rather than copying its current dimensions into the record; default flags are **zero**.

An initial native reset crash came from omitted **0x3988f / 0x398ee** thread synchronization service fixtures; adding those controlled services allowed the original reset/port code to run. No result from that harness failure is attributed to the driver. Debug builds used a scoped temporary directory and were removed when finished.

## Received-file cleanup and encoded-stream checkpoint

At this checkpoint the expanded probe passed **66,891 checks**. It executes original encoded-stream handler **0x252c0** for every mega2 type 0..1295: types zero/one do nothing beyond host flush; larger types report “Illegal type parameter 1”; all port image state remains unchanged. Dispatch slot **128**, RVA **0x81c20**, contains prefix **9**, opcode **U**, argument types **mega2, mega4**: the inherited eight reserved characters are four here. Static full-body trace **0x252c0–0x252f1** confirms no stream setup, filename, decoder or cleanup call. This shipped stub does not implement the inherited ALPHA 4 UU-encoded JPEG lifecycle; it cannot establish DELETE semantics.

Original unpacked client `riptel-unpacked.exe`, SHA-256 **953a4d08042e6ddef7d581341faefde0e1c868fe00dd57ad83be1557c2524d13**, base **0x400000**, is a separate static-analysis artifact; the packed installer executable is unchanged. Set `dll-disasm.py`'s `IB` to 0x400000 when annotating this EXE. Post-transfer routine EXE RVA **0x203e0** takes the high word of its fifth argument into global VA **0x44c0b0** at **0x203ec–0x203f8**. After displaying/converting completed files, **0x206eb–0x206fe** tests that transfer word's **bit 1** and calls thunk **0x36f82**, IAT VA **0x45b838 RIP_AddTempFile**. Driver block-mode download branches **0x24f58–0x24f6b** and their peers put the command's fourth decoded field into that high word. None reads port image flag 2. The historical draft calls that field reserved; this observation is a recovered client transfer policy, not permission to relabel image-style bits.

Driver **RIP_AddTempFile 0x765d** validates the instance/name and calls **0x18e92**, which appends the name plus newline to instance list **RIPSC%03hu.TFL** (instance ID at context+0x7a), fopen mode **a+t**. Export **RIP_PurgeTempFiles 0x769a** invokes **0x18efa**: read the list, unlink each listed name through **0x6b480**, close and unlink the list itself. It then invokes **0x452dc** to purge generated `%03huTMP*.$$$`, JPG*.TMP and MEM*.TMP files using **0x453ea**; these also do not read image-style flags. Thus later deletion of a received JPEG may arise from an independently registered temporary-file list, not image-style DELETE or completion of drawing.

Native fixtures preserve **0x765d / 0x18e92 / 0x18efa**, formatting, original list-registration and purge control flow. Controlled services **0x3f66 / 0x68f90 / 0x68ec0 / 0x6bc50 / 0x6bc90 / 0x6b480** supply a memory-only path/list/file, one scanned filename with EOF and captured unlink attempts. For all flags 0..63 and normal/raw-zero areas, registration appends without deletion; purge deletes TEST.JPG then the list regardless of image flags or area. This tests flag independence, not libc scanner EOF behavior, actual disk permissions or client cleanup scheduling. The first fixture guessed mode `a`; reading the original .data literal (RVA 0x7d10c, **file offset RVA−0x1a00**) recovered `a+t`, correcting the fixture. No original file is mutated.

Local JPEG playback callback **0x25a39** copies/expands its filename then calls **0x3880e(context,name,0)** at **0x25a72**. Wire IMAGE **0xc2c6** calls the same wrapper with retrieval enabled. Received-image client export **0x69d8** goes directly through common presentation **0x3815f**. The wrapper/common/JPEG consumers tested above never test DELETE bit 2; no flag combination causes deletion. The independent temp-list path is the actual received-file cleanup mechanism found in the original client. Hence **none of image-style bits 2, 4 or 8 deletes either a displayed local JPEG or an ignored image** in this shipped driver. This is a shipped behavior correction, not a claim about an earlier RIPterm release.

## Additional flags and precise scope

The full presentation consumer's flag **16** invokes **0x3f12f → 0x3ea2e imageWallpaper()** after successful image display. This copies the image rectangle across the viewport with **SRCCOPY BitBlt**, explicitly sets ROP2 to **13/COPY**, and consults **flag 32** for alternating half-width-offset rows; flag 32 has no effect without 16. The native full-entry probe controls this wallpaper helper as a separate GDI boundary and confirms invocation/low-word flag routing. The interpretation comes from the complete original static helper **0x3ea2e–0x3f0a5**, including the plain repeated-row path **0x3efa3–0x3f09d**. This is wallpaper copying, not file deletion or an initial clear. Default aspect-margin observations apply without wallpaper; wallpaper can subsequently overwrite margins/outside-image pixels.

All-zero wire style's fallback was exercised with a full 640×480 viewport. The lower preparer's fallback uses **physical device dimensions** from port-system +0x3a/+0x3e, not a copied image-area “disabled” state. Do not extrapolate that fixture into exact sub-viewport/offscreen clipping geometry. The issue asks state/side effects, not pixel-exact JPEG fitting. The essential verified contract is that all-zero style **does not disable viewing**; the raw-zero internal sentinel and explicit-versus-client-export guard distinction remain separate.
