## First original entry-point trace

Dispatch physical slot **98**, level-1 i, is IMAGE_STYLE **0xc39a**, arguments four XY fields, mega4 flags and 12 reserved characters. Physical slot **103**, level-1 p, is IMAGE **0xc2c6**, one mega4 reserved field and filename. IMGSTYLE original registration **0x26c77–0x26c82** binds callback **0x2f1be**.

IMAGE_STYLE accepts flags **0..63**, normalizes coordinate order through **0x3112e**, converts both corners through **0x31084**, and stores a SetRect at current 0x78-byte port record **+0x4a** with both far coordinates **incremented by one**. Flags are a word at **+0x5a**. Adjacent synchronization functions **0x34488 / 0x34489** are one-byte RETs; never apply five-byte hooks to both. Verify all-zero area behavior after this +1 storage conversion rather than assuming the inherited disable description is literally implemented.

IMGSTYLE has more surface than the HLP synopsis: zero/one argument **queries** image rectangle and flags, formatting **`%hd:%hd:%hd:%hd:%hd`** after reverse coordinate conversion **0x310f2**. First target argument is parsed by **0x98fc**, with CUR (-1) resolving current; **0x338bc** checks defined and port+0x17 bit 2 rejects a type that still needs identification. Undefined/invalid-type branch returns string constant **0x7a100** (previous issues identify `-1`) rather than defining a port. Invalid selector -5 sets variable error.

Set form requires at least **five** arguments. The local flag accumulator is initialized to **zero** at **0x2f1d1**; additional arguments starting at index 5 recognize case-insensitive **ASPECT (1), DELETE (2), NOCLEAR (4), USEPAL (8)** via **0x2f37a–0x2f3e8**; an unknown extra sets variable error before setting. It checks target protection **0x33821**, temporarily selects the target with **0x3393c**, invokes original IMAGE_STYLE, then restores previous current port. Thus the premise that IMGSTYLE has no flags facility is incomplete; native default/target/protection tests are required before documenting this.

IMAGE handler expands its filename then invokes **0x3880e(context,filename,1)**. The latter checks current port state, tests stored image right/bottom at +0x52/+0x56 for zero and normally calls **0x3815f(context,filename,1,retrieve)**. A zero stored right or bottom instead reaches **0x383b0** placeholder/drawing path without ordinary JPEG display. Because IMAGE_STYLE increments endpoints, an all-zero command initially appears to store right=bottom=1; this is a lead to verify, not a published conclusion.

Common image presentation **0x3815f** looks up JPG through **0x3f80e**, calls **0xf363** to classify the file, uses image area or viewport according to **0x34385**, then reaches **0x37fb5** for actual JPEG processing. Its success tail tests image flag **0x10** (16) and calls **0x3f12f**; the effect remains to trace. No image deletion policy is established merely by this entry-point walk. Trace final file operation and actual clear/margin consumers.

## Downstream static leads (native validation pending)

Port record +0x17 bit 2 is **viewport disabled**, not an offscreen-port type: viewport setter **0x33cc6** sets it for all-zero viewport coordinates (**0x33cf9–0x33d1d**) and clears it for a nonempty rectangle (**0x33d6b–0x33d76**). Thus IMGSTYLE’s early gate must be tested as undefined/disabled-viewport, not assumed screen-only. Original definition/protection/current-selection helpers are **0x338bc / 0x33821 / 0x3393c**; the last switches existing offscreen DCs directly and can default an undefined target, but IMGSTYLE’s earlier definition gate should prevent that path. Keep these original helpers in its probe.

Original JPEG orchestrator **0x37fb5** reads dimensions through **0x57e80**, sets per-image state context+0x56 **+0x0c** to `!(flags & 4)` through **0x296e0**, sets **+0x10** to ASPECT through **0x29700**, and sets +0x14 to zero via **0x29770**. It rejects zero `abs(right-left-1)` or `abs(bottom-top-1)`, otherwise fits/draws through **0x4d14d / 0x45d60**. It tests only bits 1 and 4 here; no DELETE/USEPAL consumer has yet been identified. The native all-zero-style test must include this one-pixel extent rejection; storing right/bottom=1 alone does not prove a visible one-pixel image.

The high-level ASPECT path calls **0x4d14d** with its clear argument unconditionally **1** at **0x38088–0x3809b**, independently of NOCLEAR. Rectangle helper **0x4d14d** calls **0x4d256** when that argument equals 1; **0x4d256** obtains stock object **4 (BLACK_BRUSH)** and calls **FillRect** through IAT **0x9667c**. It does not use the current background brush/pen ROP. Later JPEG preparation **0x29880** calls **0x4d14d** again with clear/aspect from per-image state +0x0c/+0x10 at **0x29919–0x29942**. This suggests ASPECT can black-clear even under NOCLEAR, but native captures must establish exact fill counts/rectangles and distinguish fitting from actual scan-line painting.

Lower original file/JPEG wrapper **0x45d60** writes rectangle to per-image state through **0x29720**, opens its file via **0x68f90**, initializes JPEG error/decompressor services **0x57fb0 / 0x57720 / 0x4aa40**, loops the JPEG state dispatcher **0x29c30**, closes through **0x68ec0** and destroys through **0x57790**. These loops contain no direct unlink. Original scan-line consumer **0x29ad0** passes **SRCCOPY (0xcc0020)** to StretchDIBits at **0x29bba–0x29bf0**. The file/decoder boundary may be controlled for state/effect tests while preserving preparation/fill/scan-line consumers; do not pretend a stubbed decoder proves JPEG pixel parity.

The exported client entry **RIP_ShowImageWithCurrentStyle 0x69d8** calls **0x3815f(context,name,0,0)**, whereas explicit IMAGE uses **0x3880e** then **0x3815f(context,name,1,retrieve)**. Original unpacked client imports ShowImage at VA **0x45b820**; post-transfer path from issue #19 should be revisited for any separate received-file deletion flag. The driver stores image flag 2 but its direct +0x5a consumers identified so far test only **1,4,16,32**; do not claim bit 2 actually deletes until a complete downstream/client audit establishes it. Flag 16 invokes **0x3f12f**, which redraws using **0x3ea2e** and tests bit 32; it is not itself an unlink helper.

Reset producers identified: SOFT **0x16220** stores image rectangle all **-1** and flags zero on the **current port** at **0x16298–0x162eb** before later selection/reset work. Port-system initializer **0x33d82** initializes record zero image rectangle all -1 and flags zero. Other image-flag writes occur **0x1671b / 0x169d1** (outer resets), **0x22616 / 0x2c63d** (other state consumers), **0x47441** (header/segment path). Trace exact outer gates and effects on protected/surviving ports in native tests rather than assuming full-viewport values or all-port resets.

## Native style checkpoint

New `run/riptel-image-probe DLL` passes **401 original-instruction checks** on FreeBSD 15.1 amd64 / clang 19.1.7. It SHA-verifies the unchanged DLL, disables core dumps, compiles in a task-owned temporary directory and removes the build through its EXIT trap. No GUI or real filesystem mutation runs.

Preserved: original IMAGE_STYLE **0xc39a**, IMGSTYLE **0x2f1be**, selector parsing **0x98fc**, definition/protection/current selection **0x338bc / 0x33821 / 0x3393c**, coordinate normalization/conversion and original adjacent synchronization RETs. Controlled host/display hooks: **0x45038 / 0x18cf6 / 0x18bf7 / 0x343e4 / 0x342ad / 0x34319 / 0x13c69 / 0xe6e9**; report **0x38e47**, memory string/format/decimal primitives **0x65431 / 0x655e2 / 0x65604 / 0x68440**, ASCII class table **0x87908**, SetRect IAT **0x96618**. World/device fixture is 1280×960 / 640×480. Original registration push bytes confirm callback identity before probing.

Verified all flags 0–63 accepted, 64 rejected unchanged with one report; corner ordering and far endpoint+1; all-zero command stores (0,0,1,1). Every IMGSTYLE keyword combination 0–15 replaces previous flags; no keywords resets them to zero, not retention. Literal numeric extra `3` is rejected as unknown keyword. Setter temporarily selects a valid target and restores previous current/DC. Both screen type 1 and offscreen type 4 are valid; CUR is not screen-only. Undefined slot 5 yields `-1`, no variable error and remains undefined. Invalid slot 36 sets variable error.

Original viewport-disabled bit 2 at port+0x17 yields `-1` for **getter and setter**, without variable error. A protected but enabled target still allows the getter; setter returns no text and does not change rectangle/flags. A writable enabled target is modified. Query of device rectangle (10,20,111,121) at scale 2 returns **`20:40:222:242:15`**: stored far extents are converted directly, not decremented back to original inclusive input (220,240). Record this query discrepancy if documenting the newly recovered getter.

First probe failure was an inconsistent screen-port DC fixture: current logical screen port 5 still uses port zero’s DC, whereas an offscreen port uses its own DC. Preserving original selection exposed that error; fixing fixture DC initialization resolved it. A second expectation mistakenly treated a disabled-viewport setter as NULL; the original early gate returns `-1` as the getter does. Both corrections are reflected in assertions, not classified as driver failures.
