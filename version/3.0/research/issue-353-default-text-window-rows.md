# Issue #353 — Default text-window rows and first scroll

[Issue #353](https://github.com/bbs-land/remote-imaging-protocol/issues/353) asks how the shipped driver's default rows relate to the nominal MicroANSI grid, which LF first scrolls an untouched mode 0 window, and whether the local status-bar setting changes the result. RealDeuce filed it at 16:16:44 UTC on 2026-11-26. The 16:29 UTC catch-up check confirmed the report with no comments. Branch `issue-353-default-text-window-rows` starts at fork stable `b36caf046d2cea146aa90f35aa9401d3202e665d`. [Research backlog](issue-backlog.md).

## Sources and default-window data flow

Use the original [PC Micro RIPtel 3.1 artifacts](../../../reference/rip-tools.md) under `rip-tools/artifacts/riptel-3.1-pcmicro/`. Driver RVAs are for `extracted/ripscrip.dll`, SHA-256 `83d71b358492b15bcfd3773c30a52784881a3a49a5b6e9029d986b3cba1fd5e8`, image base `0x10000000`. Client VAs are for its unpacked `riptel-unpacked.exe`, SHA-256 `953a4d08042e6ddef7d581341faefde0e1c868fe00dd57ad83be1557c2524d13`, image base `0x400000`. The [font-selection trace](issue-349-microansi-font-selection.md) identifies the client's saved preference, callbacks, drawing rectangle and MAF. Static disassembly used LLVM objdump 19.1.7. Pass VAs rather than RVAs to `objdump -d --no-show-raw-insn --start-address=… --stop-address=…`.

- The primary [2.00a4 `RIP_TEXT_WINDOW` table](../../2.0/text/RIPScrip-2.0-alpha-4.txt), §3.4.1.54, records nominal grid heights 43, 43, 25, 25, 25. In the shipped driver, the explicit `w` validation at `0x20ab8–0x20b11` reads those limits from `0xe3ec`, with ordinary mode argument 0 returned by `0x3dc6e`. Thus an explicit mode 0 window may include row 42. See the [explicit window definition trace](issue-100-ordinary-text-window-state.md).
- Startup runs the SOFT reset at `0x6401 → 0x16220`. The SOFT path calls `ripDefaultAnsiFont` at `0x164de` and the ordinary default definition helper `0x8577` at `0x164e8`. The HARD default-window path calls them at `0x1688c` and `0x16896`. The helper indexes two five-word tables at `0x859d` and `0x85a6`. The width words at RVA `0x760c8` (file `0x750c8`) are 80, 91, 80, 91, 40. The height words at RVA `0x760d8` (file `0x750d8`) are 42, 42, 24, 24, 39. It subtracts one from each and passes inclusive corners `(0,0)..(width−1,height−1)` to `0x8034` at `0x85da`. Both lookups depend on the font alone.
- Ordinary setup computes `bottom−top+1` at `0x8086–0x808f`. It stores row count at TW record `+0x25` at `0x8144`. It writes 0 to top margin `+0x2c` at `0x8157` and `rows−1` to bottom margin `+0x2d` at `0x8170`. The product of the selected font's cell height and stored row count sets the lower device boundary at `0x8252–0x826a`. For a 1024×768 client area, MAF mode 0 has 12×17 cells. The 80×42 original default window covers 960×714 pixels from the origin. The full nominal 80×43 window with the same font metrics covers 960×731. Mode 4's original height word is 39, even when applying its cell metrics would place part of the logical window beyond the drawing raster.
- The separate geometry-reset helper `0x83a5 → 0x83fb` also uses the row table at `0x84ce`, in this case indexed by the target's stored font. When resetting the already-current defined, active and unprotected TW, that path stores the matching bottom margin at `0x8502`. The documented portable live RESET recipe uses the full nominal grid of the user's default font.
- LF byte `0x0a` reaches `0x4d807` through `0x4d3ab–0x4d3ae` on the normal active-window path. It increments cursor row `+0x2b` through `0x4d81e → 0x9f16 → 0x9e9e`, then reads bottom margin `+0x2d` at `0x4d842` and live row through `0x9bc1`. When the incremented row equals bottom margin plus one, `0x4d87c` calls `0x7815`. That helper reads both margins and the mode's cell height and shifts their pixel region up by one cell through `0x93f0`. The exposed bottom row is filled with the text background. The caller at `0x4d887` returns the cursor to the bottom margin. There is one scroll for the LF at the bottom, with the reduced row count fully consumed by this path.

## Client layout and the status option

Before driver initialization, client VA `0x409a69` calls the window setup at `0x4094c2`. Its fixed display presets at `0x409940–0x409962` choose client sizes 640×480, 800×600 or 1024×768. `0x409971` measures the client rectangle. `0x4099a6` uses `SetWindowPos` to correct the outer size by the difference when the desired client extent differs. Client `0x409b1b → 0x406f3a` initializes the RIP driver with that drawing window's HWND. Driver `0x60b4` calls `GetClientRect`, then uses its width and height for the device dimensions at `0x63b7` and font cache at `0x63c7`. A client rectangle in a different MAF range can change the cell height. The row-table lookup remains fixed by the selected mode. The drawing-window procedure at VA `0x407345` sends ordinary `WM_SIZE` to `DefWindowProcA` at `0x407512–0x40751c`, with no recalculation of the default TW margin on that path.

[Issue #199](issue-199-status-bar.md) establishes that the normally initialized PC Micro client leaves status callback 14 unset. The `SBAROFF` call reaches driver `ripStatbarStatus` at `0x31b37` with selector 0. It writes only engine `+0x30c` at `0x31b85`. Even the driver's temporary hide around a physical clear (`0x2fd00–0x2fd67`) uses that same service and fills the existing driver rectangle. The status bit is absent from the default row-table readers and the LF margin consumer. For the examined startup and toggle paths, there is no extra usable row reclaimed by hiding the status indicator. The portable contract places the indicator in the presentation layer and preserves the drawing area and TW state on both toggles. [Status-bar contract](../ripscrip/5.1-text-variables.md#status-bar-state-and-presentation).

## Worked numbered-line fixture

Use a fresh TW 0 with saved `DefaultFontSize=0`, normal ANSI routing, an actual device area of 1024×768, and cursor at (0,0). Keep the initial full-height margins. Disable the client's automatic insertion of LF on CR so the input supplies exactly one LF per record. The original CR path tests that preference through `ripAddCrLf` at `0x4d3e9`. Send the two ASCII decimal digits of each number `01` through `43` in order, followed by bytes `0D 0A`. Use a fresh window for each run. For an independent repeat, evaluate `$SBAROFF$` as a RIP action before sending the text.

| Checkpoint | Shipped driver, 42 rows | Portable default TW, 43 rows |
| --- | --- | --- |
| Immediately before LF after `42` | Row 41 contains `42`, top row contains `01` | Row 41 contains `42`, top row contains `01` |
| After LF after `42` | First scroll. Rows 0–40 contain `02` through `42`. Row 41 blank with cursor there | No scroll. Rows 0–41 contain `01` through `42`. Row 42 blank with cursor there |
| After LF after `43` | Second scroll. Rows 0–40 contain `03` through `43`. Row 41 blank with cursor there | First scroll. Rows 0–41 contain `02` through `43`. Row 42 blank with cursor there |

The explicit ordinary definition `!|w0000271610` plus CR supplies corners (0,0) through (79,42), wrap 1 and mode 0. On the original it gives the 43-row result when used to define the same slot before the fixture, independent of the status option. The numbered results above are derived from the margin and pixel-scroll instructions. No original Windows client or GUI was executed.
