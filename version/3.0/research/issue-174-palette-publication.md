## Writes and return precision

- Slot **23** `D` → **0x1f46a**. Validates argument count against num+3, rejects count >256 and start >255, checks bits=8 and current palette protection, then stores the high six bits of each RGB byte. The shifts/stores are **0x1f5f7/0x1f5fa**, **0x1f602/0x1f615**, **0x1f61d/0x1f630**. Completion calls **0x3e048** at **0x1f64f**. The independent remaining-range rule is an explicit portable choice. No overrun is executed or needed to derive that choice.
- Slot **24** `d` → **0x1cf95**. Validates index 0–255, bits=8, packed color ≤0xffffff, and current palette protection. Saves full input RGB for the host GDI call at **0x1d063–0x1d06c** and stores only the six high bits through **0x1d096/0x1d0ac/0x1d0c8**. Both handlers address RGB by current PAL, record stride **0x302** and entry stride 3. They use the same protected-slot predicate **0x44508(-1)**. They update RGB bytes independently of the defined/protected flags. Existing palette lifecycle covers selection, defaults, backup and copy.
- Registration at **0x25f64** sends data flag 1, callback **0x1831e** and name literal **0x7e5b0** to **0x2556d**. Callback checks syntax and palette in-use via **0x4460b**. The undefined result at **0x18477** is `-1` (literal **0x7a100**). Otherwise **0x18493** supplies the constant 6 to format `%d;` at **0x7d08c**. The loop at **0x184b2–0x18515** traverses inclusive entries, reading raw stored RGB bytes from the exact same record and formatting with **0x7d080** `%d:%d:%d` and **0x796a8** comma. It never calls GDI or converts to display components. This result is replacement text under the enclosing HCL operation.

## GDI requests versus portable publication

- For `d`, **0x1d0d8–0x1d0eb** permits the immediate call only when the index is below the available logical count and below **236**. **0x1d0fe** calls `SetPaletteEntries` IAT **0x96474** once with the original full RGB and flag 4, and **0x1d106** requests the ordinary realization path. The stored result exists regardless of eligibility for that single-entry request.
- `D`'s bulk helper **0x3e048–0x3e125** rebuilds entries 0–235 from stored bytes and requests a bulk update at **0x3e10c**. Its near-black check **0x3e08a–0x3e09a** is on the stored six-bit components. If all are at most 3, the request is RGB black with flag 2. Otherwise it expands 63 to 255 and shifts other components left by two, with flag 4.
- Normal PAL selection **0x442c3** names the desired table and calls **0x3e2e7** at **0x4430c**. That rebuilds the available logical entries from stored RGB bytes. Its near-black check at **0x3e369–0x3e375** is after expansion and therefore only selects black for valid six-bit triplet (0,0,0). It requests upload/select/realize at **0x3e3dc**, **0x3e3fb** and **0x3e404**. The full-precision request from `d` is not retained as a second palette. Distinguish host requests from actual physical GDI colors.
- Explicit portable policy: keep `q=floor(c/4)` per component, return q with prefix `6;`, and publish `255` for q=63 or `4q` otherwise. Both valid write forms and later publication use this same result for all 256 logical entries. Near-black substitution, flags and physical slot availability belong to the original GDI boundary. A renderer retaining indexed pixels resolves the new active RGB mapping when it presents them. RGB already stored as pixels retains its own color.
- For a decoded `D` with valid start and exactly the stated colors, require `num≤256−start`, validate all inputs, and reject the whole command before any store or publication if it fails. A valid zero count is a no-op. No cross-slot behavior, prefix commit, wrap or truncation.
