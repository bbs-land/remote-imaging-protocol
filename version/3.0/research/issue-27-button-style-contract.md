## Initial primary traces, not yet a completed contract

Dispatch slot 87 is level 1 B, handler **0xb325**, 16 fields `[XY,XY,mega2,mega4,mega2×10,mega1,res5]`. Slot 107 is level 1 U (button creation), handler **0xa952**, seven fields `[XY,XY,XY,XY,mega2,mega1,mega1]`. Slot 112 is level 2 B (button-style selection), handler **0x46d08**. Button system is context +0x16, current index system +0xa, entries pointer +0, stride **0x1c**, in-use bytes system +0xc, protection bytes +0x30.

The fixed default record is `.data` **RVA 0x828e8 / file 0x80ee8**, 28 bytes:

```text
00 00 00 00 02 00 00 03 03 00 0f 00 00 00 0f 00
08 00 07 00 00 00 00 00 0f 00 07 00
```

Interpreting stores in original style handler: width/height WORDs +0/+2 = 0/0; label orientation WORD +4 = 2 (center), whose high byte +5 is separately used as other-port state by old descriptions; flags WORD +6 = **0x0300** (PLAIN 256 + BEVEL 512); bevel WORD +8 = 3; label foreground +0xa = 15, background +0xc = 0, bright +0xe = 15, dark +0x10 = 8, surface +0x12 = 7, group WORD +0x14 = 0, flags2 WORD +0x16 = 0, underline +0x18 = 15, corner +0x1a = 7. Verify initialization/reset/default selection and consumers before publishing.

Selector **0x4576f** defaults undefined entries from that record, sets in-use byte 1 and protection 0, then selects. Reset/delete **0x4558d** has distinct branches: table reset copies defaults into unprotected entries and leaves only zero in use; specific nonzero reset copies defaults and clears its in-use byte. **Suspicious current (-1) branch** copies 28 bytes to **system +0xa**, rather than a current entry address, at `0x455cd–0x455d6`; this would overwrite current selection/in-use metadata. Existing #16 table fixtures deliberately controlled this helper and do not establish the defaults or this branch. Execute it in an owned bounded fixture before deciding whether it is an original defect.

Style definition **0xb325–0xb7a3** validates orientation ≤4; colors through original `0x44385`; group <36; flags2 ≤255; at least one type bit in **0x0181**; and current button-style protection via **0x45674**. No exclusive type-bit check is present in this definition. It converts width/height with **0x31084**, bevel with the same helper's X-only form, translates colors with **0x16140**, clears/copies the current 28-byte record and stores low words. If BEVEL (0x0200) is absent it normalizes stored bevel to zero. Flags are not otherwise masked in the visible store path. The handler reads only the first fourteen argument DWORDs and writes orientation as a WORD at +4; the supplied other_port argument is not visibly read. Trace later auto-clip consumers rather than assuming this wire field works. Radio/checkbox and incompatible rendering flags still need consumer validation; source help strings alone do not settle them.

Prior [#8 bitmap derivation](issue-8-bmm-masks.md) establishes keyed loader behavior: explicit transparent-key route supports 1/4/8/24-bit, rejects 16-bit with no draw, and has a 32-bit classifier defect. It does not establish this button flags2 bit's key/source/palette selection or normal/hot fallback. Reuse that exact downstream evidence only after tracing the button caller and testing it.

## Native style/default checkpoint

New `run/riptel-button-probe DLL` passes **260,615 checks**. It executes original button-system initialization **0x4588c**, locks/unlocks **0x2badd/0x2bb24**, selection **0x4576f**, reset **0x4558d**, protection **0x45674**, complete style handler **0xb325**, color validation/translation **0x44385/0x16140** and coordinate conversion **0x31084**. Controlled GlobalAlloc returns the owned 36×28-byte table; original GlobalLock/Unlock logic uses that handle and balances its lock count. Original initialization defaults every record, selects **0**, defines only **0** and clears protection. The complete field tuple above is confirmed. **Correction to an initial interpretation:** flag 1 is CLIPBOARD and flag 256 is PLAIN, as the original reference and renderer both say; default 0x0300 is **PLAIN + BEVEL**, not clipboard. Corrected the note and fixture label; native field bytes never differed.

All 35 undefined nonzero selections copy the fixed default; slot zero is always in use and retains its already initialized record. Specific reset copies defaults, leaving zero defined and a nonzero target undefined. Table reset defaults unprotected entries and clears their nonzero definition bytes; protected fields survive. The **current (-1) reset defect is real**: in 71 valid current/protection combinations, an unprotected current reset leaves **all records unchanged**, copies the 28 default bytes into system **+0xa..+0x25**, changes current index to zero, then sets in-use[0]=1. This corrupts selection and the first 26 in-use bytes; protection bytes at +0x30 are not overwritten. Protected current reset returns AX=0 unchanged with no captured error. Exact expected system-byte arrays, not merely selected fields, are asserted. The initial static lead incorrectly mentioned protection metadata; its copy extent does not reach those bytes.

Definition matrix covers **all 65,536 low-word flag combinations**: the only type condition is `(flags & 0x0181) != 0`; every multi-type combination passes this definition and preserves its full low word. Radio/checkbox/inapplicable rendering effects are not normalized or rejected here; the later consumer still needs inspection. BEVEL absence alone forces stored bevel size zero. Full-DWORD example 0x10001 passes but stores 1. Flags2 **0..255** are retained; 256 rejects. Scales 1/2/4 × flags2 0..256 × protected/unprotected current styles prove definition-time width/height/bevel conversion and protection. Orientation 0..5 × group 0..37 prove ≤4 / <36 gates. All 36 other_port values produce byte-identical records; the wire field is unused and orientation WORD's high byte +5 remains zero.

Two fixture expectations were corrected before this pass: initializer status is **AX-only**, not a full EAX result, and slot zero cannot be tested as an undefined selector. These were harness mistakes, not original failures. All native checks run without GUI. The new wrapper/catalogue/deno task follow run/README.md and remove task temporary builds on EXIT; original files stay byte-exact. Style probe controls so far: error capture `0x38e47`, host flush `0x45038`, graphics-style/palette locks `0x3988f/0x398ee/0x447c0/0x44802`, CRT memcpy/memset `0x69e60/0x68d70`, allocator `0x65ca3` (button-system allocation only), IAT GlobalAlloc/GlobalLock/GlobalUnlock **0x964dc/0x964e4/0x964f4**. Adjacent synchronization RETs **0x2818f/0x28190** are untouched.

## Creation/renderer leads still to validate

Original creation **0xa952** converts input corners, copies current style into a transient/resident 0xa3-byte mouse/button field, then calls full renderer **0x2a4d3–0x2badc**. Field flags +0x28 WORD and flags2 +0x2a BYTE retain style values; bevel is copied as a **byte** at +0x2d. Geometry/current world dimensions and graphics font attributes are captured into that field. Definition stores device-scaled sizes; creation contains extra conversions of local size copies that must not be mistaken for used geometry. Final fixed-size fallback **0xb0c3–0xb127** reads the stored style width/height directly and adds them to the field anchor. If either stored style dimension is zero, explicit button coordinates remain the dynamic source; the eventual one-zero/end-coordinate cases need native capture.

Renderer first checks ICON flag 128, then CLIPBOARD flag 1, then the plain path. Creation nevertheless checks clipboard existence whenever flag 1 is set, even when ICON would win rendering precedence; do not omit that earlier gate from multi-type behavior. Current-style protection is not tested by this drawing constructor; explicit style edits do test it. Auto-clip mutations and any radio/checkbox later gates remain to trace.

**Transparency lead:** all three icon loader calls in this renderer (**0x2aa42 / 0x2aafa / 0x2abb9**) visibly pass key **-1**, SRCCOPY, palette mode 2 and stretch 1 to the original 16-argument loader `0x4a410`. Hot `.BMH` and normal/fallback `.BMP` paths must be captured natively. The copied flags2 local WORD `ebp-0x16` is read only at **0x2ad61 (0x20), 0x2ad80 (0x40), 0x2aded (0x20), 0x2b30b (8), 0x2b328 (0x10), 0x2b4df (2)** within this renderer; there is no visible bit-128 test. This suggests a retained but ineffective bit in these shipped paths, not an unknown color key, but do not publish that conclusion without original renderer/hover/fallback call captures. The downstream keyed loader contracts from #8 remain separate.
