## Full static selection/failure trace (native verification next)

Wire GET_IMAGE slot89 handler **0xc1cf** gates options+0x104 / current input enable, normalizes corners **0x3112e**, converts both through **0x31084**, adds **one to each converted far coordinate**, installs DC/clip, clears port-system+0x26, then calls shared **0x2866**. It ignores the helper's status and restores clip/caret. The helper computes its bitmap dimensions using **low-WORD far-minus-near plus one**, so wire conversion and helper each contribute an increment. Its source rectangle and destination dimensions can differ; preserve the actual compositor request rather than assume unscaled capture.

Helper **0x2866–0x29ff** begins CX=-1 and BX=old clipboard index (system+0xa). If old pointer=-1, it scans definition bytes slots1..35 for the **first unused**, without searching for an existing offscreen type. No free slot reports failure and leaves pointer=-1 / definitions / current selection unchanged. A free candidate is assigned immediately. If an old pointer exists, it first calls **0x33112(ctx,old,0)**. Protected deletion failure restores old clipboard pointer and exits, without trying another slot. Successful deletion also restores the old index before redefining that exact target. If creation **0x3326f** fails, helper clears pointer=-1 and returns; it does not restore the deleted old port. This implies allocation failure can lose old definitions/pixels, contrary to the issue's proposed retention, but execute the real branches before publishing.

Original protection **0x33821** tests record+0x17 bit1. Original deletion **0x33112** routes an explicitly targeted current port through its current branch, then **0x3302c** frees resident query/bitmap/DC, resets record (retaining index), sets its image area -1 and clears definition. Deleting current unprotected nonzero port sets current index to **0**. There is no shared-helper same-source no-op gate before this. Thus an assigned clipboard equal to current source may delete source, switch to0, recreate target and copy from0; this must be tested explicitly. Protected current target rejects unchanged. A clipboard pointer of0 is not a normal allocated clipboard and the deliberate-port0 delete gate rejects it.

Original port creation **0x3326f–0x33789** checks target protection before deletion, then deletes the old target record if its index is nonzero. It checks bitmap budget, creates DC, creates bitmap, selects it, clears it, then only at **0x33753** marks type4/defined and stores final viewport/extents. Failures are not transactional. Budget/DC/bitmap/select-object failures leave distinct cleared/stale handle fields, and the old bitmap may already have been deleted. Created-source pointer is read **after** destination allocation at0x2982 from live current index; no saved source index exists. Shared compositor **0x134d0** can choose stretch because rectangle extents differ, trims against viewports, then uses **0x136a9/0x13763**. Helper returns AX=1 after that call regardless of compositor result; no copy-failure rollback.

### Protected explicit LOAD_BITMAP duplicate

Original `1b` handler0xc569 calls the renderer0x4a410 at0xc957 **before** testing duplication. Palette adoption0x49120 is inside that renderer at0x4a4cd. For a different explicit duplicate1..35, a defined target goes through original portDelete0x33112 with force0 at0xca2d. The protected-target branch0x331bb–0x331f7 returns failure without selecting0 or deleting anything. Caller0xca35–0xca4e then cleans up and returns; it neither calls creation/compositor nor reaches wallpaper. This is not DEFINE_PORT's separate selection/fallback sequence.

Consequently the initial current-port image and any completed palette adoption survive; there is no rollback. Current selection, target definition/resources and clipboard pointer remain unchanged. No replacement pixels are written to the protected target. A protected **screen** port can nevertheless share underlying pixels with the initial drawing port, so ordinary overlapping initial paint is not undone or prevented by duplicate protection. For an independent offscreen target its pixels remain intact. If explicit target equals current, the earlier equality gate skips duplication entirely.

Native bitmap probe now restores original deletion bytes for this case, retaining original protection0x33821, and uses defined/protected target7, current2, pointer7 and flags19. Original renderer is an observer in this routing phase: it records the already-issued palette-adoption/draw request, not actual Windows palette effects. Every port-record byte and pointer/current compare unchanged, exactly one protection error is captured, and no allocation/copy/wallpaper occurs. Full-renderer tests elsewhere retain original palette and bitmap paths within their documented service boundary.

### Completely clipped is not a zero-size returned rectangle

The premise that the loader first produces a clipped visible rectangle is false. Geometry0x49340 fills missing far coordinates from image dimensions. Renderer0x4a53f–0x4a591 writes the **requested device rectangle** to the caller before GDI drawing; there is no viewport intersection in this producer. Ordinary StretchDIBits wrapper0x4e77b–0x4e811 accepts even return0, and returns1 after the call (even its -1 diagnostic path does not change that return). Thus a valid, nonempty ordinary bitmap outside the viewport can finish rendering successfully with zero visible pixels and a **nonempty, unclipped** returned rectangle. An actual earlier decoder/resource/compositing failure follows the separate failure/placeholder branch before duplication; invisible geometry alone is not that failure.

After a successful load, flag1 still performs normal target selection/protection/replacement. Explicit different target1..35 is created with returned width/height at0xca53–0xca63. Its compositor0x134d0 can reject the entirely outside source, but0xca91–0xca99 ignores that status, leaving the new port defined with its initialized background. No old definition/pixels are restored. If deleting the explicit target also removed the clipboard assignment, deletion clears the pointer and this explicit route does not reassign it. The duplicate0 route instead uses0x2866 and assigns the new clipboard; its existing extra far increment makes a returned4×2 rectangle allocate **5×3**. A protected assigned clipboard still rejects before deletion, as documented above.

Native full-renderer case: original `1b` reads the controlled24-bit4×1 BMP, requests `(40,30)..(44,32)` outside the4×1 destination, changes none of its four pixels, reports success and calls the captured clipboard helper with exactly that **4×2** rectangle. Independent original0x2866 cases, with pointer absent/7, allocate **5×3**, reject the outside source during original compositor trimming, retain the new clear bitmap/pointer and current0, and destroy old7 when assigned. This combines actual producer/consumer observations; it does not claim an end-to-end Windows raster run or zero-dimensional allocation.

### LOAD_ICON failure retains clipboard state

Missing ordinary lookup:0xccdf–0xcd3a calls placeholder0x383b0 at0xcd18 and returns. Renderer failure with graphics enabled:0xcde6–0xce5a calls the placeholder at0xce24, cleans up and returns. Neither path calls0x2866, deletion, creation or a pointer-clear store. The clipboard-enabled success path is separate at0xce5f–0xce86. With graphics disabled the renderer-failure path also skips that clipboard call. Lookup status2 takes its separate exit0xccb2–0xccda without a placeholder or clipboard operation.

Placeholder0x383b0–0x3880d was traced as well: it loads BROKEIMG from disk/resources, uses the **current port's DC** at0x385d6–0x385e3 and0x38703–0x38774, invalidates the drawn region and may issue host diagnostics. It contains no clipboard deletion, definition or pointer-clear operation. Its own rendering/resource failure can omit the visual placeholder; it does not change the clipboard contract. There is no clearing-before/after-box order to implement.

Therefore both clipboard0 and clipboard1 retain the prior pointer and port definitions/resources, including protected targets, screen targets, an assignment equal to current, and a stale assignment to an undefined port. Current selection stays current. If current is the clipboard port, placeholder rendering can alter **that port's pixels**; that is ordinary drawing, not deletion or erasure of the clipboard. A different offscreen clipboard's pixels remain untouched. Screen ports can share physical drawing pixels.

Native routing matrix covers clipboard0/1, defined screen/offscreen/undefined record fixtures, protection0/1, lookup/renderer failure and pointer absent/0/2/7:192 cases. It captures placeholder current/pointer and compares the complete port array afterward. Placeholder rendering and the viewport predicate are controlled services; the static placeholder trace establishes its actual DC routing and absence of clipboard mutations. No Windows placeholder-pixel oracle is claimed. This differs from GET_IMAGE allocation failure, which really clears its pointer after deleting an unprotected assigned target.
