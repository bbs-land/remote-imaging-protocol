Screen serializer `0x236fb` writes **768 raw RGB bytes from the current palette entry**, then `0x237ce` captures the physical screen DC from **port record zero +0x6c**, regardless of current port. Its capture dimensions are client rectangle width/height from port-system +0x32..+0x3e; BitBlt is (0,0), SRCCOPY. It calls generic bitmap serializer `0x21f91` with include-palette flag **1**, so the stream contains **another 768-byte current palette copy after the bitmap metadata/pixels**. Do not miss that nested palette because the outer serializer already saved one. Metadata is type/width/height/stride as low words, then planes/depth as bytes, raw bitmap bytes, then palette; no viewport, current-port index, status bar, styles or button table is serialized.

Screen restore `0x2391a` reads the outer palette, copies it directly into the **currently selected palette's RGB bytes** with memmove `0x6b9a0` and uploads via original `0x3e2e7`. ### Capture, target palette and ports

For the controlled 8×4, one-plane eight-bit screen, the original stream is exactly **1,578 bytes**: outer RGB 768, bitmap metadata 10, indexed pixels 32, nested RGB 768. Both RGB blocks match the palette selected at save. Source DC is port zero's screen DC 10 while current drawing DC is a distinct offscreen DC 11; the saved pixel bytes match the screen, not the offscreen contents. Original restored BitBlt targets physical screen DC 10 at (0,0), SRCCOPY, saved dimensions, with one screen invalidation. Codec layout and both palettes execute unchanged; no bitmap serializer/reader is replaced.

Matrix: save and restore palette indices independently **0/5/17/35**, with target record flags **0/1/2/3**. Restore overwrites only the live selected palette's 768 RGB bytes, leaves that index and its flags untouched, bypasses protection/definition, and performs **two** original palette uploads. All 256×3 uploaded components are asserted against original six-bit-to-eight-bit conversion (63 → 255, otherwise ×4). A complete pre/post palette-table comparison excludes only that target's RGB bytes. Thus saving palette 5 then restoring while protected palette 17 is current writes 5's saved RGB into 17, preserves 17's protected flags and current selection, and leaves palette 5 alone unless it was also the current target.

Current port changes from 1 at save to 35 at restore; the formerly current port is deleted/retyped/redefined and protected, and both viewport rectangles are changed. Complete port records and port-system state remain byte-exact across screen restore. Its pixels still target port zero. Style/button/environment selections and record sentinels are unchanged. Ordinary SAVE includes neither STYLE nor BUT, and it contains no saved current-port number or viewport to restore; those contradictory inherited sentences must be replaced.

### Real status-bar owner and SAVEALL palette phase

Original SBAROFF/ON callbacks `0x3075a/0x30782` call status service `0x31b37`; STATBAR `0x307aa` queries it. The actual owner is **engine-state byte +0x30c**, via instance +6 → engine object → state pointer; optional host callback is engine callback table +0x38. The new fixture invokes original SBARON before save and SBAROFF afterward, using that exact original owner/callback and asserting both cached status and callback count stay unchanged during screen restore. This supersedes the initial stand-alone fixture Boolean. Original background-palette service `0x32cc5` also runs against this real engine fixture, with no desktop calls. Static review of the eight save/restore families shows no serialized engine status byte or call to `0x31b37`; SAVEALL does not acquire status restoration by adding the other seven tables. The 7.2 status-bar capture claim is not shipped behavior.

Native coupling runs original family-6 screen save then family-4 palette save, and restores them in the same relative order as RESTOREALL. Screen restore first overwrites current palette **17** from saved palette **5**. The subsequent **whole-palette** restore `0x22fcb` restores all 36 records/flags plus the saved current index **5**, then original palette selection `0x442c3` uploads 5. Protected 17's temporary overwrite is undone by that full-table restore; all saved table bytes return. The final screen pixels match the snapshot. This tests the actual screen/palette components; the all-eight wrapper order is independently proven by the captured original dispatch matrix, not by pretending other family codecs ran in this coupled fixture.

### Aliases, protection, consumption and real file helpers

All numbered slots 0..9 run through original parameterized **and original numbered** save/restore callbacks, against real screen serialization/manager state. For each, protected snapshots block overwrite, allow restore, and resist the post-restore delete; unprotected overwrite retains one occupied slot and unprotected restore consumes it. Slot protection is backup-record flags bit 4, distinct from palette-entry/port protection. Base restore repeats without consumption. A failed read-open on numeric RESTORE leaves the screen unchanged but still deletes an unprotected saved record and releases occupancy, matching wrapper dispatch regardless of helper failure. Ten original PUSH/POP snapshots restore LIFO and unlink on consumption; full PUSH at occupancy ten makes no file request. This is not a general audit of all corrupted/oversaturated backup-manager states.

Original filename producer yields **`CACHE` + backslash + `00300001.$$$`** for instance 3/counter 1. Original CRT open/read/write/close/unlink are captured as RAM-file effects; all snapshots retain their generated names/bytes across ordinary close and base restore. Re-save unlinks the old file; consume/delete unlinks and clears its record. Original manager uninitialization `0x246f0` unprotects numbered slots and calls family cleanup `0x24660` for all eight families before releasing its memory. There is no RIPTERM.SAV/RIPTERM0.SAV operation in these traces. The directory comes from engine configuration +0x16; call it the configured engine directory rather than claiming a particular operating-system temporary location. A conforming implementation can use private memory for the same observable snapshot lifecycle; literal inherited RIPTERM*.SAV names are not a protocol requirement.

The one intermediate compile failure while adding the engine fixture was undeclared fixture arrays after a text-edit mismatch; fixed those declarations and the status assertion. No original runtime crash or failed observation occurred. Current file capacity is 32×32 KiB virtual files; allocations and GDI objects are closed/released between cases. Scope: controlled un-clipped indexed bitmap services establish original capture/restore arguments, bytes and ownership, not Windows clipping/raster/palette-display parity.
